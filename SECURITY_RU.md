# Безопасность проекта

## Ключи

- публичный publishable/anon key Supabase допустим в клиенте только вместе с
  корректными RLS-политиками;
- `SUPABASE_SERVICE_ROLE_KEY` используется лишь локально для миграции и
  никогда не добавляется в `NEXT_PUBLIC_*` или `VITE_*`;
- `.env.local`, журналы и временные данные исключены из Git.

## Доступ

Редакционные роли хранятся отдельно от читательского профиля.
`owner/admin/editor` проверяются сервером. Назначать роли может только
владелец; база не позволяет удалить или понизить последнего владельца.

Черновики и редакционные версии недоступны анонимному читателю. Предпросмотр
работает только после входа и получает заголовок `noindex`.

### MFA редакции

Редакционная панель поддерживает TOTP через встроенный MFA-контур Supabase Auth.
На первом этапе подключение выполняется добровольно в разделе «Настройки», чтобы
не заблокировать владельца до успешной проверки первого фактора.

После подтверждения TOTP Supabase делает `aal2` доступным для учётной записи.
Новая сессия с паролем сначала получает `aal1`; панель направляет такого
редактора на `/mfa`, а `requireStaff()` не разрешает server actions, пока код
второго фактора не поднимет сессию до `aal2`.

QR-код и секрет подключения существуют только во временном состоянии страницы
настройки: они не записываются в local/session storage, журнал аудита или базу
приложения. Подтверждённые факторы на первом этапе из интерфейса не удаляются,
чтобы снизить риск случайной потери доступа. Рекомендуется подключить второй
резервный TOTP-фактор после проверки первого.

Жёсткое требование `aal2` на уровне RLS базы - отдельный второй этап. Его можно
включать только после успешного production-enrollment владельца и проверки
восстановления доступа.

## Пользовательский контент

Комментарии и рейтинги доступны гостям, но проходят через защищённые
RPC-функции:

- ограничены длина и число ссылок;
- действует лимит частоты;
- жалобы попадают в собственную очередь модерации;
- HTML посетителя не публикуется.

## Медиа и HTML

Загрузки ограничены безопасными растровыми форматами, очищаются от метаданных
и перекодируются. SVG не принимается. HTML статей и страниц очищается на
сервере; скрипты, iframe, обработчики событий и опасные схемы URL удаляются.

## Перед выпуском

Проверить отсутствие секретов в diff, применить миграции по порядку, сделать
резервную копию Supabase и включить MFA у владельца GitHub, Supabase и
хостинга.
