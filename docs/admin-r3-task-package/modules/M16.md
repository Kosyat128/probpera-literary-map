### M16. Согласованность Site Studio, главной, меню и баннеров — P2

**Основание.** Site Studio, компоненты, токены, шрифты и releases уже существуют. Их публичный дизайн и системные 3D-компоненты не входят в переделку. [E19]

**Реализация.** Карта: какое поле редактируется в homepage/site-copy/studio/banners/menus, где его master-значение, версия и публичный resolver. Устранить подтверждённые независимые записи одного поля через общий адаптер/явное владение, не создавать ещё одну конфигурацию оформления.

Связанные изменения — существующий draft release, preview и атомарный выпуск; если старый модуль публикует немедленно, UI честно обозначает это до операции. Предпросмотр с теми же resolvers, версией настроек и adaptive-режимом, без доступа к произвольному CSS/JS. Сохранить запреты системных компонентов.

Проверить отмену, scheduled release, устаревший draft, конфликт двух вкладок и групповой rollback. При неудачном выпуске нельзя смешивать половину новых токенов с половиной старых настроек. Публичные тексты и контент не затрагиваются. Для меню сохранять иерархию, уникальные идентификаторы и допустимые URL; для баннеров — desktop/tablet/mobile assets, расписание, приоритет и видимость.

**Приёмка.** Одно поле имеет один источник истины; preview совпадает с выпускаемым вариантом; изменение studio не переделывает полку и глобус.

**Уточнение R2.** Детальная целостность меню/баннеров вынесена в M22, текстов/шаблонов — M24, файлов шрифтов — M23; это расширения существующей студии, не новые параллельные конструкторы. Rollback release обязан учитывать действующую версию и чужие более новые изменения по фактическому RPC, даже если форма отправляет только releaseId. Планирование проверяется с явной зоной. Неподдерживаемые свойства системных компонентов не разблокируются произвольным CSS/JS.
