### M19. Страницы: согласованность HTML/JSON и рабочая редакция — P0/P1

**Основание.** В просмотренном `createPageAction` непустой текст переводится в `content_html`, а `content_json` записывается пустым документом. `PageEditor` предпочитает `page.content_json || page.content_html`. Пустой объект документа является truthy: первоначальное содержимое редактора может не соответствовать сохранённому HTML. Это вывод из двух исходников, а не подтверждение потери конкретной production-страницы. Проверка media identity не заменяет проверку содержимого документа. [R2E01]

**Сделать.** Выделить единый контракт загрузки и сохранения страницы на основе уже используемых TipTap extensions, санитизации, медиа-идентификаторов и модели версий. Не создавать вторую систему редакторов. Различать отсутствующий JSON, валидный пустой JSON, повреждённый JSON и валидный содержательный JSON. Сам факт наличия объекта не определяет, какая редакция правильная.

Для новой страницы из простого текста строить согласованные JSON и HTML до первой записи. Безопасно обрабатывать угловые скобки и текст, который не заявлен как HTML; не интерпретировать пользовательский plain text как произвольную разметку. Для legacy-страницы с непустым HTML и пустым JSON показать явный режим совместимости/предпросмотр, построенный существующим безопасным парсером. Загрузка не должна молча переписывать БД. Перед переходом к новому представлению сохранить исходный снимок и показать содержательную разницу. Если оба представления непустые и расходятся, не угадывать правильное по длине или времени клиента: показать конфликт и сохранить оба до решения.

Проверять текстовые блоки, таблицы, ссылки, изображения, подписи, литературу и порядок элементов. Не требовать байтового равенства HTML и JSON: их канонические безопасные проекции сравниваются содержательно, без новых орфографических или типографических преобразований. Не менять исключённую подсистему дефисов/тире или её вызовы. Повреждённое/неподдерживаемое содержимое не превращать в пустую страницу для дальнейшего сохранения.

**Разделение редакций.** Проверить фактическую поддержку рабочих черновиков страниц. В просмотренном обработчике обычное сохранение обновляет `pages`, а сохранённый статус может оставаться published. Если отдельной рабочей модели нет, довести непубличный черновик страниц через минимальное расширение существующей модели, не вводя общий новый CMS-фреймворк. Опубликованная редакция остаётся читаемой до отдельного выпуска. Не реализовывать черновик переводом самой опубликованной записи в draft: это снимет страницу с сайта. Предпросмотр читает выбранную рабочую редакцию, не отправляет её в индекс или публичный экспорт.

Смена slug — отдельное действие с проверкой конфликтов, старого URL и связанных ссылок, по M13/M21. Если историческая страница содержит специальный canonical, изменение заголовка не должно его перезаписывать. Восстановление использует M06 и те же проверки, что обычное сохранение. Статус отложенной публикации не добавлять без работающего обработчика; поддержку обозначать по фактическим возможностям.

**Точки входа.** `app/(dashboard)/pages/actions.ts`, `pages/[id]/page.tsx`, `pages/[id]/preview`, `components/PageEditor.tsx`, общие rich-editor и page revision helpers. Пути сверить на текущем HEAD.

**Приёмка.** Новая непустая страница открывается с тем же содержимым; повреждённый JSON не заменяет HTML пустотой; обновление черновика опубликованной страницы не меняет её публичный текст; одинаковые проверки действуют в редакторе, истории и публикации.

### Уточнение R3: preview страниц должен следовать draft-контракту
[R3E12] Сейчас отдельная страница preview читает canonical pages.content_html и использует notFound при отсутствии data без разбора query error. После введения рабочего page draft она должна читать выбранную редакцию тем же безопасным адаптером, иначе UI сохранит B, а preview покажет A. Доступность БД, отсутствие объекта и запрет доступа различаются по общей политике. Смена режима просмотра не сохраняет/не публикует контент.

Переносить весь публичный renderer в админку не требуется: выдели минимальную общую безопасную проекцию и нужные presentation tokens. Действующие ограничения HTML/ресурсов проверяй на synthetic fixtures; оригиналы не переписывать. Проверка небезопасного содержимого не даёт разрешения менять исключённые нормализаторы.
