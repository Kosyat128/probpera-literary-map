### M06. История, сравнение и безопасное восстановление — P1

**Основание.** Текущий общий restoreRevisionAction обновляет целевую запись, отдельно пишет аудит и запрашивает public build; для основного издания есть многошаговая компенсация. UI предлагает немедленную публикацию восстановленной версии. [E09]

**Реализация.** Сравнение текущей сохранённой, рабочей и исторической версии: поля, RU/EN, контент, медиа, ссылки, метаданные. Сравнение read-only и без повторного сохранения статьи. Для длинных HTML использовать ограниченный безопасный diff без выполнения скриптов; не выводить полный мегабайтный snapshot в каждом ряду списка.

По умолчанию «Восстановить в черновик» для сущностей с существующей черновой моделью. У статьи восстановление использует рабочий черновик, а не опубликованную articles-запись. Если черновик уже есть, предложить сравнить/сохранить его отдельно; не уничтожать его молча. Приёмка: значение публичной редакции не изменилось до отдельного выпуска; внутренние технические invalidation-события оцениваются по контракту M04, а не запрещаются целиком.

Не приклеивать к старому немедленному action новое название. Для сущностей без черновой модели показать реальное последствие и безопасный preview; создать специализированный непубличный restore proposal только при необходимости, не общий дублирующий CMS. Немедленный откат — отдельное действие с достаточной ролью, причиной, ожидаемой версией и явным подтверждением.

Использовать проверенные специализированные RPC/инварианты обычного сохранения; восстановление не должно обходить RU/EN bundle, права, primary edition и ограничения Site Studio. Многозаписные изменения, аудит и outbox сделать атомарными в БД, где этого ещё нет. Не рассчитывать на компенсацию после обрыва процесса как на эквивалент транзакции.

Не восстанавливать владельца, привилегии, deleted_at, серверные поля и одобрения из произвольного snapshot. Для новой редакции повторно оценить нужные проверки; журнал append-only. Показывать понятного исполнителя, причину операции, истинную причину недоступности восстановления. Не выдавать любую нересторируемую запись за «Объект удалён».

**Приёмка.** Старую версию можно изучить без записи, восстановить безопасно, отменить proposal и выпустить отдельно; при сбое транзакции нет частичного отката связанных сущностей.

**Уточнение R2.** Контракт восстановления не должен требовать отсутствия любых технических outbox строк: обязательна неизменность опубликованной редакции и отсутствие несанкционированного выпуска. Для действий с каскадными зависимостями использовать M21/M22. Дифф показывает пропущенные запрещённые поля и причины, не восстанавливает одобрения по одному клиентскому JSON. Snapshot с неизвестной будущей схемой не загружается как пустой объект; unsupported и corrupt различаются.
