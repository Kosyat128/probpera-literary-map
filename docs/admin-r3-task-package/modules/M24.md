### M24. Тексты сайта и шаблоны: версии, переменные и отказ перевода — P1

**Основание.** В `saveSiteCopyAction` перевод изменённых строк может выполняться до `save_site_copy_block`; ошибка runtime-gate/провайдера прерывает сохранение исходных правок. Защита ручного EN и CAS уже есть. В действиях Site Studio время преобразуется через `new Date(candidate)`; семантику зоны нужно согласовать. Редактор статей поддерживает personal/shared templates: их права и текущую реализацию следует сверить на HEAD, а не предполагать готовность всех операций. [R2E12, R2E13, E05]

**Надёжное сохранение.** Доступность переводчика не должна быть условием сохранности введённых RU/EN. До внешнего запроса обеспечить сохранение рабочего снимка/задачи в действующем защищённом контуре. Если политика требует согласованный bilingual release, отделить сохранение черновика от публичного применения: не выпускать неготовую половину. Не заменять ранее опубликованный EN пустым результатом и не пересоздавать вручную редактированную строку. Ошибка перевода оставляет явную задачу на повтор и исходный ввод. Долгий перевод не должен удерживать один HTTP-запрос; использовать M07. Существующий kill switch, выбор моделей, лимиты и запрет реальных платных вызовов в текущем задании сохраняются.

**Контракт строки.** Для каждого реально управляемого ключа показать назначение, место использования, локаль, исходное значение, override и происхождение. Не начинать массовый перевод или переименование ключей. Действия «сбросить override/наследовать» и «задать намеренно пустое значение» различаются там, где пустое значение разрешено. Если контракт ключа запрещает пустоту, объяснить это до сохранения, а не убирать строку молча.

Плейсхолдеры, ICU/plural/rich-text tokens проверять только в тех строках, где эти механизмы действительно применяются. Нельзя вводить фиктивную обязательную ICU-схему для простого текста. Сохранить именованные переменные, допустимые теги и экранирование; сравнить обязательные параметры RU/EN и справочника. Не разрешать подмену `__proto__`/зарезервированных объектов при работе с динамическими словарями; существующие произвольные `interface.*` ключи проверить по назначению, а не отключить все кастомные ключи. Отчёт об осиротевшем override не является разрешением его удалить.

При разных формах, редактирующих один системный блок, сохранить неотправленные поля. Патч имеет явный набор изменённых ключей; пустой набор не очищает всё. CAS/проверки выполняются в транзакции. Слияние неконфликтующих ключей допустимо только с проверенной семантикой и сохранением ручного происхождения, иначе показать сравнение. Не хранить несколько равноправных блоков с одним systemKey, выбирая «последний» как случайный master; сверить уникальный контракт в RPC и миграциях.

**Шаблоны.** Проверить сохранение, применение и удаление personal/shared templates в существующих действиях: приватный шаблон не читается другим аккаунтом; редактор не меняет чужой shared без соответствующего права; удаление шаблона не меняет уже созданные статьи. Применение вставляет копию после понятного выбора/preview, не подменяет существующий текст по умолчанию. Санитизация та же, что для обычного ввода. Смена шаблона не выдаёт прежние проверки прав/фактов за подтверждение нового содержимого.

**Приёмка.** При недоступном переводчике правки восстановимы; placeholder mismatch обнаруживается до применения; reset/inherit работает без удаления соседних ключей; права personal/shared проверяются сервером; неприкосновенный текст и нормализаторы не изменены.
