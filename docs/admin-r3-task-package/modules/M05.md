### M05. Редактор статей и защита рабочих черновиков — P0/P1

**Реализация.** Сначала исследовать существующие ArticleEditor, working-draft actions, atomic bundle, autosave/recovery и preview. Не вводить второй черновик с конфликтующей семантикой.

Разделить действия «Сохранить черновик», «Передать на проверку», «Запланировать», «Выпустить». Не менять опубликованную редакцию обычным автосохранением. В закреплённой панели показывать dirty/saving/saved/offline/conflict/unknown-outcome с временем именно подтверждённого сохранения. После ошибки сохранять ввод, курсор, выбранный язык и доступный контекст формы.

Оптимистическая конкуренция: хранить серверный revision/token точности без потерь; не сериализовать timestamp с потерей микросекунд. Проверять ожидаемую версию в транзакции; не реализовывать read-then-write без условия. При конфликте — сравнение с серверной версией и сохранение своей копии, а не автоматический last-write-wins. Поздний ответ старого автосохранения не сбрасывает более новые локальные изменения.

Обработать уход через sidebar, Ctrl+K, внутренние ссылки, back, закрытие/перезагрузку и истечение сессии. beforeunload — только дополнительная защита, не механизм сохранения. При повторной авторизации не включать черновик в URL и не открывать его другому пользователю. Использовать существующее защищённое серверное восстановление. Постоянное локальное хранение неопубликованного текста не добавлять без отдельной политики; если оно уже есть, проверить scope пользователя/материала, срок и очистку на logout.

Предпросмотр показывает выбранный черновик, язык и режим экрана; не публикует его, не индексируется и не раскрывает его через публичный URL. Проверить изображения, списки, таблицы, сноски/библиографию и длинные материалы. Ошибки полей связать с конкретным контролом и общей сводкой. Ссылки и HTML проходят существующую безопасную обработку; её нельзя отключать ради точного восстановления опасной разметки.

**Приёмка.** Повторное сохранение не вводит новых преобразований содержимого; сохранение при сетевой ошибке/конфликте не уничтожает текст. Исключённое baseline-поведение из ограничений не исправляется. Действия с черновиком не запускают публичный выпуск.

**Уточнение R2.** Общие изменения редактора проверять вместе с M19/M20: новый clean/saved сигнал относится к принятой версии, не к нажатию кнопки. Истёкшая auth-сессия должна приостанавливать запись, не уводя пользователя без защищённого восстановления и не копируя весь текст в callback URL. Применение или удаление editor-template не может заменить тело существующей статьи без соответствующего явного действия; права personal/shared в M24.

### Уточнение R3: достоверный предпросмотр, а не похожая карточка
[R3E06] В просмотренной article preview загрузка/рендер обложки опираются на cover_external_url; cover_media_id в исходной проекции не выбран. Проверить managed-cover сценарий и вынести минимальный общий resolver URL/alt/focus/приоритета, совпадающий с public renderer. Не импортировать всю Vite/3D-публичную часть в admin Worker ради повторного использования одной функции.

Выбор preview должен иметь точную идентичность: entity, locale, origin(local/autosave/working draft/published), revision/fingerprint. По умолчанию показывать, что именно просмотрено. Не выдавать сохранённый B за несохранённый C, не привязывать review новой редакции к старому preview. Безопасный локальный preview допустим, если он явно обозначен и не создаёт публичную публикацию; не записывать его скрыто ради просмотра.

RU/EN, внешняя/managed обложка, галерея, таблица и библиография должны пройти сравнение на фиксированных viewport. Узкая рамка вокруг desktop CSS недостаточна, если реальные responsive правила продолжают видеть широкий viewport. Выбери лёгкую изолированную страницу/iframe/доказанный эквивалент, совместимый с CSP/X-Frame-Options и нужным origin, не ослабляя глобальную защиту ради iframe. Отсутствующий EN и ошибка его чтения различаются.

Для небезопасного legacy HTML проверять безопасную проекцию и существующие sanitization/URL contracts, а не разрешать активный контент ради визуального совпадения. Исходный контент не массово ремонтируется.
