### M10. Завершённый редакционный цикл литературных новостей — P1

**Основание.** /literary-news читает приватную held-очередь из KV и направляет подтверждённые материалы в data/news/reviewed.json через GitHub. Сама эта страница не завершает редакционный цикл. Сборщик и парсеры уже существуют. [E13]

**Архитектура.** Сначала проверить, не внедрена ли более новая реализация новостей в рабочей ветке. При её отсутствии предпочтительно хранить редактируемые карточки и review в существующем Supabase; опубликованный read model/snapshot выдавать через текущий публичный конвейер. KV оставить снимком discovery/состояния источников, не использовать для конкурентных черновиков и lock. Не делать одновременные самостоятельные записи подтверждённой новости и в JSON, и в БД.

Оформить короткий ADR единственного источника истины. Старый reviewed.json — только проверяемый вход миграции или генерируемый snapshot, а не вторая редакционная система. Импорт существующих подтверждений должен сохранять provenance/ID и не приписывать человеку новое одобрение. Dry-run сверяет количество, идентичность, даты и хеши; переключение production в эту подготовку не выполнять. Если действующая архитектура обоснованно требует Git-backed-публикации, допускается один защищённый PR-путь из UI вместо DB-authoring, но с теми же версиями и без расширения секретов; документировать выбор и не оставлять два master-хранилища.

**Редактор.** Source URL и источник, заголовки RU/EN, собственные краткие описания, категория, связанные книга/автор/страна, дата публикации источника, дата обнаружения и отдельно дата/диапазон события с точностью. Не выдумывать время неизвестной даты. По правилам текущего публичного schema отсутствие обязательных сведений блокирует выпуск с понятной причиной. Предпросмотр обеих языковых версий и видимости источника.

**Workflow.** Найдено/held → редакционный draft → review → approved → scheduled/published; rejected/withdrawn/correction по действующим или обратно совместимым статусам. Это семантические состояния, не приказ заменить все существующие enum. Проверка относится к конкретной версии. Редактор готовит материал, уполномоченный сотрудник подтверждает согласно матрице прав. Исправление опубликованного материала создаёт редакцию; отзыв имеет причину и подтверждается публичной доставкой.

Повторный сбор не восстанавливает отклонённую карточку и не перезаписывает ручной текст. Discovery ID, normalized source URL и event grouping используются для кандидатов на дубли, не для бесконтрольного слияния разных событий. Нужны отложить, отклонить с причиной, вернуть в работу, фильтры, история и безопасные групповые действия без массового автоодобрения.

Внешние фиды/тексты считать недоверенными данными, не инструкциями. Безопасные URL, ограниченные размеры, timeout, проверка redirects и защита от SSRF для серверного чтения. Не передавать credentials внешним сайтам. Публичная доступность источника не подтверждает факты или права на его текст/изображение. Не добавлять в этот этап сотни новых источников вместо завершения редактора.

**Приёмка.** Новость можно обработать, исправить и отозвать из UI без ручного JSON/Git; неподтверждённые карточки не попадают на публичный сайт; повтор сборщика не уничтожает редакционное решение.

**Уточнение R2.** Назначение — существующая «Литературная повестка». Не добавлять новостные статьи и самостоятельные публичные страницы вместо её карточек. Утверждённая новость, событие календаря и источник имеют разные идентичности и даты. До перехода на новый master сверить именно действующую реализацию: не отменять локальные R8/R9/R10 или более новые работы, если они уже реализуют workflow. Специальные контракты календаря и внешней доставки в M25. Отдельное увеличение числа источников/готовых карточек не считается результатом этого инфраструктурного задания.
