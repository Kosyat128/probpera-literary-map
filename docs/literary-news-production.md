# «Проба Пера · Новости»: публичная литературная сводка

Панель находится на [главной странице](https://probpera.ru/#book-day), справа от «Книги месяца». Интересный факт расположен под ней; обе колонки имеют общий нижний край. На телефоне используется одна колонка. Русский и английский выбираются существующим переключателем в шапке сайта.

## Что публикуется

В начальном выпуске - 33 проверенные двуязычные записи. Девять тем: новые книги, премии, экранизации, памятные даты, фестивали, литературное наследие, открытия, некрологи и издательские события. Реестр содержит 29 источников: международные организации и издания Европы, Северной и Латинской Америки, Азии, Африки и Океании.

Карточки - собственные краткие пересказы со ссылкой на исходную публикацию. Подтверждение источника, дата публикации, дата события и дата редакционной проверки хранятся раздельно. Анонс не становится сообщением о состоявшемся событии автоматически. Истёкшие анонсы исключаются из текущей выдачи для отправки, но сохраняются в проверенном архиве панели с исходными датами; неизвестная дата не заменяется временем работы сборщика.

## Как обновляется публичная панель

1. Компонент загружается при приближении к разделу книги месяца. Место для него резервируется заранее; новостная логика не входит в начальную загрузку главной.
2. Браузер получает `GET https://news.probpera.ru/api/literary-news/feed?contract=2&view=archive&timeZone=Europe/Moscow`. Публичный Cloudflare Worker возвращает только проверенную подборку с `mode: "reviewed"`; локальный сервер посетителю не нужен. Отдельный Custom Domain позволяет API работать независимо от прямого размещения основного домена на GitHub Pages. CORS разрешает чтение с `https://probpera.ru`.
3. Панель проверяет обновления раз в минуту. Новые карточки появляются после нажатия «Обновить список»; исправления и отзывы применяются сразу. При сетевом сбое остаются уже полученные карточки.
4. Workflow **Refresh literary news sources** запускает сбор из реестра на 7-й и 37-й минуте каждого часа, а также после изменения новостных источников или проверенной подборки в main. Расписание GitHub Actions не является гарантией точного времени запуска. Фактическое время последнего поиска хранится отдельно от времени выдачи API.
5. Сборщик сохраняет состояние источников и непроверенные находки в приватном Workers KV. При ошибке чтения хранилища запись не выполняется. Сбой отдельного источника сохраняет его предыдущие находки и время последнего успешного обращения.

API сохраняет ограничение на один загруженный граф данных: одновременный запрос другой версии, часового пояса или режима может получить `503` с `Retry-After`. Панель, серверный сбор готовых новостей и проверка эксплуатации повторяют только такой явный краткий отказ до трёх попыток, с задержкой 1-2 секунды и тем же общим таймаутом 20 секунд. Предыдущий ответ освобождается до повтора; отмена запроса прерывает ожидание. CORS открывает браузеру `Retry-After`. Все серверные попытки проходят через существующий счётчик запросов; повтор чтения не обходит лимиты и не разрешает повторную отправку в Telegram.

Сбор источников отделён от проверки и публикации. Включённая подготовка новых заметок принимает только подтверждённые первоисточником факты и двуязычные материалы, прошедшие проверку качества. Непроверенные находки остаются в приватной очереди. Условия подготовки, восстановление прерванной публикации и ограничения отправки описаны в `docs/literary-news-native-preparation.md`.

## Работа редактора

[Раздел литературных новостей в редакторской панели](https://admin.probpera.ru/literary-news) доступен авторизованной редакции. Он показывает найденные заголовки, исходные ссылки, доступные даты и причины ожидания проверки. Публичный API не раскрывает содержимое этой очереди.

Для публикации редактор открывает первоисточник, сверяет дату и статус события, готовит короткий текст на обоих языках и добавляет запись в `data/news/reviewed.json`. Обязательны уникальный `id`, тема, `kind`, дата события, время проверки, источник, RU/EN-заголовок и RU/EN-описание. Дата публикации может быть `null`, если источник её не указал. `eventKey` объединяет сообщения об одном и том же событии; разные этапы премии должны иметь разные ключи.

Изменения проходят pull request и обязательные проверки защищённой main. Исправление или отзыв оформляется изменением или удалением той же записи. История Git сохраняет автора и содержание изменений. После слияния сайт и публичный Worker публикуются из одного коммита; новая подборка доступна без ручного обновления страницы.

## Часовые пояса и функции читателя

Часовой пояс берётся из настроек браузера без геолокации и определения IP. «Сегодня», порядок новостей и отбор анонсов рассчитываются для посетителя. Календарная дата юбилея или фестиваля сохраняет свой день; время конкретной публикации переводится в местное время. Переход через полночь и смена часового пояса обновляют выдачу.

Доступны совместимые фильтры периода, темы, региона, непрочитанного и избранного, а также поиск по русским и английским текстам. Закладки и отметки прочтения хранятся в браузере. Источники, время их проверки и ошибки доступны в раскрываемом разделе «Источники и проверка».

## Выпуск и эксплуатация

- Worker: `scripts/workers/literary-news-worker.mjs`, конфигурация `scripts/wrangler.literary-news.jsonc`.
- Публичный API обслуживает только чтение. Произвольные адреса источников и операции публикации в нём отсутствуют.
- Источники задаются неизменяемым кодовым реестром `scripts/lib/literary-news-sources.mjs`; сетевой сбор ограничен размером, временем, числом запросов и разрешёнными адресами.
- Состояние хранится только в ключах `literary-news:v1:source-state` и `literary-news:v1:held-queue` существующего приватного KV. Редакционные каталоги и их контрольные суммы не меняются.
- GitHub-секреты `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN` используются на сервере. Секреты не передаются браузеру, не сохраняются в данных и не выводятся в диагностику.
- Для сборщика токену требуется `Account > Workers KV Storage > Edit` в аккаунте сайта. Успешное развёртывание Worker само по себе не подтверждает право читать или обновлять KV через REST API. Ошибка 401 останавливает сбор без перезаписи прежних данных.
- Публикация Pages сначала развёртывает API и проверяет его коммит, RU/EN-данные и три часовых пояса. Ошибка API останавливает выпуск новой страницы.
- Ручная проверка работающего API: `node scripts/verify-literary-news-live.mjs`. Повторный сбор - ручной запуск workflow **Refresh literary news sources** на main.

Локальный изолированный просмотр остаётся доступным через `node scripts/preview-literary-news.mjs` и `news-preview.html`; он явно использует `/__literary-news/feed` и помечен как локальный прототип. Обычная главная страница использует публичный контракт.

Архитектура использует [Custom Domain Cloudflare Worker](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/) и [чтение приватного KV через binding](https://developers.cloudflare.com/kv/api/read-key-value-pairs/). Получение внешних публикаций выполняется отдельно от запросов читателей.

Расширенная панель «Литературная повестка» на главной использует проверенный архив. Начальная подборка и полный список доступны в том же блоке: поиск, темы, регионы, источники, период публикации, порядок чтения и постраничный просмотр сочетаются с избранным и непрочитанными материалами. Подробности раскрываются внутри карточки. Новые карточки применяются явно, чтобы обновление сохраняло выбранный материал и положение просмотра.

Архив запрашивается только с `contract=2&view=archive`. Его отдельная политика `reviewed-v2-archive-explicit-withdrawals` входит в контрольную сумму полной публикации. Она сохраняет прошедшие подтверждённые анонсы с исходными датами; интерфейс отмечает их как завершённые анонсы. Явные удаления, проверка источников, дат и двуязычного содержания действуют и в архиве. Обычная лента и отправка в Telegram продолжают требовать политику текущих новостей `reviewed-v2-explicit-withdrawals`, поэтому архивный анонс не получает разрешение на новую отправку. Браузер принимает архивную политику только при явном запросе архивного режима.
