# PRODUCT COMPLETENESS / NO-RETURN CONTRACT — V12

## Purpose

This contract prevents a technically impressive but operationally
incomplete handoff. Codex must close all internal gaps now rather than
leave them as future discovery for the owner.

## Complete means

- user can install, start, learn, search, read, explore, personalize,
  use child mode, work offline, recover errors and receive updates;
- owner can edit content, approve child material, add customization,
  manage products/rights/releases and operate support without source edits;
- developers can reproduce builds/tests and understand boundaries;
- store packages are ready except genuine account/signing/license actions;
- security/privacy/accessibility/performance evidence exists;
- backup/restore/incident/rejection processes exist and are tested.

## Forbidden final remnants

- critical TODO/FIXME;
- placeholder/fake portrait/flag/cover;
- mock-only purchase critical path;
- untested migration;
- empty error/offline state;
- missing iPad/landscape flow;
- hidden adult leak in child mode;
- undocumented SKU/price/territory;
- unlicensed Disney asset;
- hardcoded secret/price;
- manual database copying;
- one-off command not documented;
- backup not restored;
- owner operation requiring code edit without justification;
- “external blocker” used to hide incomplete internal work.

## Final gap sweep

Codex performs:

1. Requirement traceability audit.
2. Screen/state audit.
3. Platform parity audit.
4. Child bypass audit.
5. Purchase lifecycle audit.
6. Offline/update/rollback audit.
7. Rights/provenance audit.
8. Accessibility/localization audit.
9. Performance/device audit.
10. Owner operation audit.
11. Store submission audit.
12. Documentation-command verification.

Any internal gap reopens implementation and testing.

## Owner confidence package

The owner receives:

- one architecture map;
- one operations manual;
- one external-actions list;
- one artifact inventory;
- one traceability report;
- one maintenance calendar;
- one support/incident matrix;
- one release/rollback procedure;
- one rights/licensing dashboard/process;
- a final PR with CI evidence.

## Status rule

`COMPLETE` only if internal traceability is 100% and mandatory tests pass.
`COMPLETE_WITH_EXTERNAL_BLOCKERS` only if remaining items need owner/store/
merchant/signing/legal/licensing/manual review. No other status may be
presented as finished.

## Moderation no-return completion

The owner must not discover after implementation that the product still
lacks basic submission material. Before FINAL HANDOFF Codex must complete:

- exact store identity/name matrix;
- whole-binary age/content inventory;
- explicit Apple Kids Category decision record;
- Google target-audience worksheet;
- RuStore age/paid/standalone worksheet;
- stable review account and Parent PIN health checks;
- IAP sandbox and Restore paths;
- account deletion;
- privacy/Data Safety/permissions congruence;
- exact-RC screenshot sets;
- rights-clean artifact scan;
- current toolchain/target snapshot;
- store-specific review dossiers;
- rejection/resubmission playbook;
- owner submission checklist.

Concept mockups, expiring reviewer credentials, unlicensed hidden assets,
manual privacy guesses and a generic “submit the app” instruction are
forbidden final remnants.

Store-console, signing, tax/banking, legal approval, final price, licensed
IP agreements and manual submission may remain external. All code,
evidence, templates and exact owner steps around them must already be
complete.

## Owner-minimal no-return completion

The final handoff is incomplete if the owner must:

- edit source code;
- manually synchronize metadata values across stores;
- discover secret names;
- invent reviewer instructions;
- diagnose SDK/permission requirements;
- find screenshots in the repository;
- prepare DSA/export/developer-verification evidence from scratch;
- manually build release artifacts;
- reread old prompts;
- choose between contradictory defaults.

Codex must produce one owner input, one approval report, one handoff folder,
one set of draft-upload commands and one final external-action list.
