V12 extends every V11/V12 owner-minimal, moderation, child-safety,
commerce, rights and site-canon rule with mandatory production-quality
Russian and English support.

Обязательные языки первого публичного выпуска:

```text
ru — Русский
 en — English
```

Release profile:

```text
SAFE_PAID_BILINGUAL_V1
```

This profile is the previous safe paid profile plus a complete English
application, content, store, legal, support and reviewer surface.

## 2. Product names / Названия

Russian:

```text

Brand/subtitle: Проба пера
Guide character: Планетка
```

English:

```text
App name: Literary Planet
Brand/subtitle: Proba Pera
```

`Proba Pera` is the stable English brand form. Do not randomly alternate
between “Trial of the Pen”, “First Attempt”, “Pen Test” or other literal

## 3. Runtime locale behavior / Поведение языка

- Source/editorial locale: `ru`.
- Required release locales: `ru`, `en`.
- Unsupported system locale fallback: `en`.
- On devices with Russian as preferred language, start in Russian.
- On other devices, start in English.
- Always provide a visible language selector in onboarding and Settings.
- A language change preserves the same globe, camera, country, writer,
  work, child profile, purchase state, download and route.
- Language switching must never recreate a second globe or reset Canvas.
- The chosen app language is stored locally before first content render,
  preventing Russian/English flash.
- Child mode remains child mode after language changes.
- Parent may lock a child profile language; language selection never
  bypasses age or Parent Gate policy.
- Language and sales territory are separate concepts.

## 4. Complete English scope / Полный английский контур

English is not limited to buttons. Before V12 bilingual release, English
must cover:

- all critical and noncritical UI;
- onboarding, errors, empty/offline states and accessibility labels;
- native system-facing strings on Android and iOS;
- Base Edition writer profiles, biographies, countries, works and facts;
- child biographies, journeys, quizzes and Planetka dialogue;
- Starter Set, skins, stands, backgrounds and optional product;
- search aliases, sorting and transliteration;
- offline packages and downloaded manifests;
- store metadata and exact-build screenshots;
- privacy, terms, support and account deletion;
- reviewer instructions and moderation dossiers;
- admin/CMS translation workflow;
- owner handoff and post-build guide.

An untranslated Base Edition entity may not silently appear in Russian in
an English screen. Publication is blocked or the entity is explicitly
unavailable in English until approved. V12 release requires 100% Base
Edition English coverage.

## 5. No low-quality machine translation / Запрет сырого машинного перевода

Codex may generate a draft, but production publication requires:

1. source hash and immutable factual source;
2. glossary and translation-memory pass;
3. named-entity/title verification;
4. placeholder/markup/citation parity;
5. independent semantic review pass;
6. back-translation or structured meaning-diff check;
7. child reading-level and sensitivity check where applicable;
8. rights check for translated quotations/titles/audio;
9. locale preview and layout test;
10. approved publication state.

Raw automated translation, hallucinated English book titles, invented
writer aliases, translated URLs, changed dates or lost citations are P0
release blockers.

## 6. English names and titles / Имена и названия

- Use an established English writer name from authoritative library,
  publisher or reference sources when available.
- Preserve native/original name separately.
- Search includes Russian, English, native-script and verified
  transliteration aliases without creating duplicate writer records.
- Use a documented published English work title when verified.
- If no established English title exists, show the original title plus a
  clearly marked transliteration or descriptive translation; never present
  a guessed translation as an official edition title.
- A public-domain source text does not automatically make a modern English
  translation, cover or audiobook public domain.
- Quotations use a rights-cleared English translation or are paraphrased as
  summaries; do not fabricate a canonical quotation.

## 7. Platform localization / Локализация платформ

Apple:

- app binary supports Russian and English;
- use String Catalogs/native localized resources for system surfaces;
- support per-app language behavior provided by iOS/iPadOS;
- localize App Store metadata and exact-build screenshots for English and
  Russian;
- if a new app record is created, English (U.S.) is the recommended primary
  metadata fallback with Russian localization; if an existing record has a
  different primary language, do not change it without a migration review.

Google Play / Android:

- support Android per-app language preferences for `ru` and `en`;
- include only declared locales in the production bundle;
- provide complete default resources so unsupported device locales cannot
  crash the app;
- use English (United States) default store listing and Russian translation
  for a new global listing, unless the owner approves another existing
  configuration;
- custom store listings require their own manually supplied translations;
  do not rely on automated store translation.

RuStore:

- Russian storefront remains the primary submission surface;
- the app must offer Russian and English selection;
- moderation instructions are Russian with an English backup;
- no mixed-language screen or English-only legal dead end.

Web/PWA:

- localized routes and metadata;
- `lang`, `hreflang`, canonical and locale alternates;
- no duplicate-content loops;
- browser/system locale negotiation plus explicit switch;
- locale-specific offline caches and manifests;
- English fallback for unsupported locales.

## 9. English child experience / Детский режим на английском

Planetka English dialogue is adapted, not mechanically translated. It

Do not use celebrity or character voice cloning. Do not record or upload a
child’s voice.

3. ACCOUNTLESS-FIRST DEFAULT
======================================================================

To reduce review, privacy and owner burden:

- native paid app core is guest-first;
- local favorites, history, child profiles and settings work without an
  account;

this must be the minimum necessary commerce identity and have deletion,

1. КАЧЕСТВО ВИЗУАЛА

Текущая идея детской планеты близка к нужному направлению, но итоговый

- полноценные руки и ноги без обрезания кадром;
- мягкая детская пластика;
- продуманные состояния и анимации;
- согласованность со светом, подставкой и фоном;
- визуальный уровень не ниже готовой «Литературной планеты» сайта;
- отсутствие ощущения случайной картинки, дешёвого шаблона или сырого
  игрового ассета.

2. НЕ ОДИН ДЕТСКИЙ СКИН, А ЦЕЛАЯ ЛИНЕЙКА

Нужно создать data-driven систему, в которой ребёнок и родитель могут
выбирать несколько разных детских вариантов планеты. Минимальный набор
для первой качественной версии:

- «Детский глобус» - понятная учебная карта, животные, чистая география;
- «Весёлая Планетка» - главный дружелюбный персонаж с лицом, руками и
  ногами;
- «Планетка-путешественница» - дорожный образ, рюкзачок/компас как
  отдельные аксессуары;
- «Планетка-сказочник» - книги, звёзды, мягкое волшебное оформление;
- «Планетка-космонавт» - космический образ и совместимый космический фон;
- «Планетка-зверята» - аккуратные изображения животных по регионам;
- «Планетка-океан» - морская тема и жители океана;
- «Планетка-пазл» - развивающая поверхность без нарушения географии;
- «Планетка-радуга» - мягкая цветовая тема;
- «Планетка-ночник» - спокойная вечерняя тема без пугающих эффектов.

Архитектура не должна быть ограничена этим списком. Владелец планирует
добавлять много скинов: реалистичных, исторических, художественных,
шуточных, сезонных и коллекционных. Новые скины должны добавляться через
каталог/админку и ассет-манифест, а не через переписывание центрального
компонента глобуса.

3. «ПЛАНЕТКА» - ГЛАВНЫЙ ГЕРОЙ ДЕТСКОГО РЕЖИМА

Имя детского героя: «Планетка».

Планетка - не декоративная наклейка и не единичная анимация. Это главный
проводник ребёнка по приложению. Она:

- встречает ребёнка;
- объясняет управление;
- предлагает безопасные литературные путешествия;
- помогает найти страну, писателя или произведение;
- показывает короткие подтверждённые факты;
- даёт подсказки;
- реагирует на успех;
- мягко сообщает об отсутствии сети;
- сопровождает onboarding;
- может быть свёрнута, чтобы не мешать чтению или исследованию;
- использует только заранее написанные и редакционно подтверждённые
  реплики, без открытого генеративного AI-чата.

4. МНОГО ПОДСТАВОК И МНОГО ФОНОВ

Система должна масштабироваться на большое количество:

- реалистичных музейных подставок;
- деревянных, металлических, бронзовых, золотых и каменных подставок;

- статических, 2.5D и полноценных 3D-фонов.

Текущие звёзды и небесный фон сохранить как сцену, включённую в базовую платную редакцию, и
улучшить без разрушения существующей производительности. Поверх неё
создать полноценный Background Scene Engine с плавной заменой сцен,
освещения, окружения и разрешённого ambient sound.

5. ДЕТСКИЕ ЛИТЕРАТУРНЫЕ ПЕРСОНАЖИ В ФОНАХ

Архитектура должна поддерживать тематические фоны с настоящими узнаваемыми
персонажами детских книг, например с Винни-Пухом и другими героями, НО:

- только при наличии подтверждённых прав или подходящего public-domain
  основания для конкретной версии изображения и конкретных территорий;
- нельзя копировать Disney-образы, защищённые иллюстрации или иные
  узнаваемые коммерческие дизайны без лицензии;
- нельзя создавать «почти такого же» персонажа для обхода прав;
- каждый такой набор должен иметь rights record, источник, владельца прав,
  разрешённые территории, срок лицензии и store availability;
- при отсутствии документов набор остаётся blocked и не попадает в
  production/store;
- до получения лицензий приложение должно быть полностью готово на
  оригинальных персонажах проекта, прежде всего на Планетке, и на
  проверенных public-domain/owner-supplied материалах.

6. ТОЧНЫЙ ВОЗРАСТ И ОГРАНИЧЕНИЕ ИМЕННО ПРОИЗВЕДЕНИЙ

Недостаточно пометить автора как «детского». Один и тот же писатель может
иметь произведения для разных возрастов и взрослые произведения.

Родитель должен указать точный возраст ребёнка в полных годах. Возраст
можно изменить только через Parent Gate. Приложение обязано проверять
возраст на каждом уровне:

- страна;
- писатель;
- отдельное произведение;
- подборка;
- поиск и подсказки;
- рекомендации;
- история;
- избранное;
- offline package;
- deep link;
- уведомление;
- магазинный/тематический набор.

В карточке автора ребёнок видит только отдельно одобренные произведения,
подходящие его возрасту. Сам факт наличия детских книг у автора не открывает
остальные произведения.

7. НИКАКИХ ИИ-ПОРТРЕТОВ И ВЫДУМАННЫХ ОПИСАНИЙ

Все уже добавленные владельцем реальные портреты и подтверждённые
описания являются owner-locked source material.

Запрещено:

- заменять их AI-сгенерированными портретами;
- «улучшать» лица генеративной дорисовкой;
- создавать реконструкции внешности писателей;
- подменять реальный портрет похожим лицом;
- выдумывать факты;
- автоматически публиковать сгенерированную биографию;
- автоматически переписывать авторские статьи;
- заменять подтверждённое описание коротким AI-summary без согласования;
- выдавать непроверенный перевод за подтверждённый текст.

Для каждого опубликованного портрета и описания сохранить provenance,
источник, права, статус проверки и checksum. Если портрета нет, показать
нейтральную фирменную заглушку без лица, а не синтетического «писателя».
AI может использоваться Codex только как инструмент программирования и
подготовки чернового внутреннего кода. Публикация фактического контента
разрешена только после явного редакционного подтверждения.

8. ОТДЕЛЬНОЕ РАЗЛИЧИЕ МЕЖДУ ФАКТИЧЕСКИМ И ХУДОЖЕСТВЕННЫМ СКИНОМ

Каждый скин получает режим:

- factual-modern;
- factual-historical;
- educational-child;
- artistic;
- humorous;
- seasonal;
- licensed-story-world.

Фактическая география, hit-testing и координаты всегда используют
проверенный atlas. Художественный или шуточный скин не должен незаметно
выдаваться за точную современную карту. В Explore Mode можно включить
программные современные границы и подписи поверх художественной
поверхности либо автоматически переключаться на совместимый учебный
слой, сохраняя выбранную тему окружения.

Этот блок должен быть перенесён Codex в docs/mobile/OWNER_LOCKS.md и
проверяться отдельными автоматическими contract tests.

0B.1. ПРИОРИТЕТЫ ВЛАДЕЛЬЦА ПО ЭСКИЗУ
---------------------------------------------------------------------

1. ЗАСТАВКА И ЗАПУСК

Первый экран эскиза близок к желаемому направлению, но итог должен быть
заметно чище и ближе к реальной фирменной заставке сайта:

- полностью оранжевый фон точного brand orange;
- официальный знак «Проба пера» с пером;
- маленький фирменный знак в верхнем левом safe-area;
- центральная композиция с официальным логотипом/названием без самодельной

- минимум декоративного шума;
- никаких AI-иллюстраций;
- никакого белого/чёрного промежуточного кадра;
- второй загрузочный экран использует настоящую готовую 3D-планету,
  настоящую подставку и существующую библиотечную либо звёздную сцену;
- прогресс отражает реальные этапы инициализации, а не фальшивый процент.

2. ДЕТСКИЙ ВЫБОР ПЛАНЕТЫ, ПОДСТАВКИ И ФОНА

Эскиз задаёт обязательный отдельный customization flow с вкладками:

- «Планеты»;
- «Подставки»;
- «Фоны»;
- «Образы Планетки» либо «Персонаж».

Нужны несколько действительно разных детских планет, а не один asset с
изменённым цветом. Минимум:

- учебный детский глобус;
- «Весёлая Планетка»;
- сказочная Планетка;
- космическая Планетка;
- Планетка-путешественница;
- Планетка-зверята;
- океанская Планетка;
- спокойная вечерняя Планетка.

Подставки и фоны также являются независимыми слоями и комбинируются через
совместимость, preview и transactional apply/revert.

3. ПЛАНЕТКА - ГЛАВНЫЙ ГЕРОЙ

Центральная позиция эскиза с Планеткой является owner-approved продуктовым
направлением. Планетка должна быть главным проводником ребёнка:

- появляться в child Home;
- приветствовать;
- предлагать безопасные действия;
- сопровождать обучение;
- помогать исследовать страны, писателей и книги;
- показывать редакционно подтверждённые факты;
- реагировать на успех;
- объяснять offline/error state;
- сворачиваться, когда мешает чтению или работе с картой.

Планетка использует scripted guide engine и не является открытым AI-чатом.

4. БОЛЬШОЙ КАТАЛОГ СКИНОВ, ПОДСТАВОК И ФОНОВ

Эскиз магазина - только начало. Архитектура должна поддерживать десятки и
сотни будущих items: от точных музейных и исторических глобусов до
шуточных, сказочных, пиратских, космических, сезонных и детских тем.
Владелец должен добавлять новые items через админку/manifest без изменения
центрального runtime-кода.

5. ПИСАТЕЛИ - ТОЛЬКО РЕАЛЬНЫЕ МАТЕРИАЛЫ

Нижний блок эскиза должен быть реализован не декоративными лицами, а
настоящими владельческими ассетами и проверенными данными:

- реальные портреты из public/assets/writer-portraits и действующего
  portrait registry;
- реальные флаги из public/assets/country-flags с сохранением attribution;
- реальные имена, годы жизни, произведения и описания из source-of-truth
  базы;
- только verified/editorially approved biographies;
- реальные обложки только при подтверждённых правах;
- при отсутствии портрета/обложки - нейтральная фирменная заглушка без
  синтетического лица и без фальшивой обложки.

0B.2. ЧТО ИМЕННО БЛОКИРУЕТ ЭСКИЗ, А ЧТО ОН НЕ БЛОКИРУЕТ
---------------------------------------------------------------------

Эскиз блокирует иерархию и смысл следующих экранов:

A. Launch:

B. Child customization:

C. Planetka:

D. Shop:
- featured bundle;

E. Literary content:
- список писателей с реальными портретами;

- показ на глобусе;
- интересные факты;

Эскиз НЕ блокирует:

- монеты/сердца как валюту;
- AI-изображения известных персонажей;
- неправильные портреты;

- буквальное копирование слишком тесной плотности карточек.

В production необходимо улучшить mockup:

- убрать случайные/ошибочные надписи;
- убрать фальшивую внутреннюю валюту в v1;
- показывать локализованную реальную цену магазина;
- увеличить читабельность;
- выстроить единый button hierarchy;
- использовать реальные assets;
- сократить визуальный шум;
- обеспечить accessibility;
- обеспечить child safety;
- сохранить фирменный характер сайта.

0C. ВЫСШИЙ OWNER-LOCK V12: ОСНОВА - ЛИТЕРАТУРНАЯ ПЛАНЕТА НА САЙТЕ
======================================================================

Это требование имеет высший технический и визуальный приоритет после
безопасности ребёнка, прав и требований магазинов.

ОСНОВА МОБИЛЬНОГО ПРИЛОЖЕНИЯ - НЕ НОВАЯ ПЛАНЕТА И НЕ ПЕРЕРИСОВАННЫЙ
МАКЕТ. ОСНОВА - ФАКТИЧЕСКИ РАБОТАЮЩАЯ «ЛИТЕРАТУРНАЯ ПЛАНЕТА» НА САЙТЕ
«ПРОБА ПЕРА» В ТЕКУЩЕМ РЕПОЗИТОРИИ.

Codex обязан сначала зафиксировать и переиспользовать:

- реальную sphere geometry;
- реальную UV/texture alignment;
- существующие издания и стили глобуса;
- действующую camera/focus mathematics;
- country picking;
- writer/country focus;
- текущий one-Canvas contract;
- текущие stars, sky, atmosphere, lighting и background fallback;
- реальные страны, координаты, флаги и границы;
- реальную базу писателей;
- реальные портреты из утверждённого portrait pipeline;
- подтверждённые биографии и произведения;
- существующую i18n, accessibility и performance policy;
- текущие owner locks сайта.

Каждая новая мобильная функция должна строиться ВОКРУГ этого ядра:

- Планетка является presentation/guide layer поверх существующей сферы;
- детские скины являются новыми surfaces/overlays в совместимом registry;
- подставки являются отдельными объектами вокруг той же планеты;
- 3D-фоны являются отдельными environments вокруг того же Canvas/runtime;
- литературные персонажи являются rights-gated story-world layers и
  образовательными маршрутами вокруг реального глобуса;
- mobile shell не создаёт вторую географическую систему;
- сайт и приложение используют единый source of truth.

Запрещено считать экранный эскиз готовой планетой. Эскиз задаёт UX и
композицию, но production показывает фактический глобус сайта и реальные
данные репозитория.

Обязательные regression contracts:

- один и тот же country ID выбирается на сайте и в приложении;
- одна и та же координата фокусируется одинаково;
- одна и та же проверенная biography не расходится между платформами;
- mobile customisation не ломает desktop/web surface;
- child presentation не меняет geographic source;
- characters/backgrounds не участвуют в hit testing стран;
- после закрытия mascot/story world остаётся точный Explore Mode;
- новые модули не создают второй WebGL renderer;
- открытый PR по глобусу сначала проверяется на пересечение и не
  дублируется.

В STAGE 0 создать отдельный документ:

docs/mobile/LITERARY_PLANET_FOUNDATION_LOCK.md

В нём перечислить точные файлы, компоненты, contracts, tests, assets и
commit SHA, которые являются основой приложения. Каждый последующий Stage
должен ссылаться на этот документ.

======================================================================
0D. ВЫСШИЙ OWNER-LOCK V12: ЛИТЕРАТУРНЫЕ ПЕРСОНАЖИ В ДЕТСКОМ РЕЖИМЕ
======================================================================

Детский режим должен быть не только фильтром писателей и не только экраном
Планетки. Он должен включать качественную «Вселенную героев книг» с
популярными русскими и зарубежными литературными персонажами.

Главный постоянный герой приложения - оригинальная Планетка. Литературные
персонажи являются гостями, спутниками и проводниками отдельных
StoryWorld, но не заменяют Планетку и не превращают приложение в набор
несвязанных франшиз.

Персонажи должны использоваться образовательным образом:

ПЕРСОНАЖ -> ПРОИЗВЕДЕНИЕ -> АВТОР -> СТРАНА -> ТОЧКА НА ГЛОБУСЕ ->
ПРОВЕРЕННЫЙ ФАКТ -> БЕЗОПАСНОЕ ЗАДАНИЕ/ПУТЕШЕСТВИЕ.

Каждый доступный ребёнку персонаж должен иметь:

- stable character ID;
- каноническое имя;
- оригинальное имя;
- source work;
- source author/tradition;
- country/region connection;
- approved age range;
- child-safe description;
- approved dialogue;
- exact rights status;
- permitted territories;
- approved visual source;
- approved voice source либо captions-only;
- provenance/checksum;
- StoryWorld association;
- author/work deep links;
- allowed interactions;
- safety tags;
- store/entitlement policy;
- expiry/delisting policy.

Никакой популярный персонаж не может попасть в production только потому,
что он известен или указан в этом задании. Сначала rights audit, затем
original-or-licensed asset approval, затем editorial/age review, затем
production export.

Обязательное разделение:

1. OWNER-ORIGINAL
   - Планетка и собственные персонажи проекта;
   - могут входить в базовую поставку после art/editorial approval.

2. FOLKLORE / CLASSIC PUBLIC-DOMAIN CANDIDATE
   - персонажи фольклора и классических произведений;
   - статус конкретного текста, перевода, иллюстрации, имени, торговой
     марки и территории всё равно проверяется;
   - создаётся собственная оригинальная визуальная интерпретация по
     литературному источнику;
   - нельзя копировать поздние мультфильмы, фильмы, игры, игрушки,
     издательские иллюстрации и фирменные дизайны.

3. SPECIAL RIGHTS REVIEW
   - правовой статус зависит от страны, версии, перевода, особого закона,
     товарного знака или более поздней адаптации;
   - production blocked до письменного clearance.

4. LICENSED REQUIRED
   - современные и защищённые персонажи;
   - в коде и админке может быть candidate slot;
   - в production/store они отсутствуют до active license.

5. BLOCKED
   - нет документов, истёк срок, территория не разрешена, asset не
     подтверждён или дизайн копирует чужую адаптацию.

Жёстко запрещено:

- генерировать AI-lookalike защищённого героя;

правообладательских документов и production assets.

8. ФИРМЕННАЯ ЗАСТАВКА И ONBOARDING
======================================================================

Системная splash:

- полностью оранжевый фон;
- точный канонический orange сайта, извлечённый из текущих brand tokens;
- официальный brand icon;
- без белого/чёрного flash;
- корректно в light/dark;
- без растягивания;
- одинаковый perceived colour на Android и iOS насколько позволяет

- самый ранний кадр не должен показывать WebView background.

Учитывай, что системный Android splash может центрировать icon. Сохрани тот
же orange, чтобы переход был бесшовным.

Фирменный app splash:

- сплошной оранжевый фон;
- значок «Проба пера» с пером слева наверху;
- safe-area;
- внешний отступ около 20-24 dp после проверки на реальных размерах;
- логотип полностью виден;
- мягкое появление 180-280 ms;
- без долгой обязательной анимации;
- плавный переход в onboarding/Home;
- reduced motion без движения;
- инициализация content manifest и local DB не должна бесконечно держать
  splash: при задержке показать branded loading state с доступным текстом.

Проверки:

- cold-start video;
- warm start;
- Android light/dark;
- iOS light/dark;
- узкий экран;
- notch/Dynamic Island/cutout;
- landscape;
- no flash;
- logo top-left;
- correct safe-area;
- exact brand color;
- no layout shift после загрузки шрифтов;
- no frozen splash после recoverable content error.

Onboarding максимум 4 основных шага, но с отдельным безопасным parent flow:

1. «Исследуйте литературу на глобусе».
2. «Находите писателей и произведения по странам».
3. «Меняйте внешний вид своей планеты».
4. Выбор: «Обычный режим» / «Режим для ребёнка».

Обычный режим не требует регистрации.

При выборе режима для ребёнка onboarding передаёт управление Parent Gate и
обязательно выполняет:

1. Коротко объяснить родителю, зачем нужен возраст.
2. Предложить создать локальный child profile без обязательного настоящего
   имени.
3. Указать точный возраст в полных годах от 3 до 17.
4. Опционально выбрать reading level; возраст остаётся главным ограничением.
5. Выбрать разрешённые/нежелательные темы.
6. Установить PIN.
7. Настроить звук, narration и motion.
8. Показать, что покупки и внешние ссылки защищены.
9. Выбрать один из детских наборов оформления, включённых в базовую платную редакцию.
10. Запустить приветствие Планетки.

Не проси полную дату рождения, геолокацию, школу, email ребёнка или
разрешение на рекламу. Возраст позже меняется только через Parent Center.

Если ребёнок использует приложение без завершённого parent setup:

- не открывать общий режим;
- не угадывать возраст;
- показать нейтральный экран «Позовите взрослого»;
- предложить Parent Gate;

11. «ПЛАНЕТКА» - ГЛАВНЫЙ ГЕРОЙ И ДЕТСКАЯ ПЛАНЕТА-ПЕРСОНАЖ
======================================================================

Имя героя в русском интерфейсе: «Планетка».

Планетка создаётся как отдельный presentation/guide layer поверх готовой
географически корректной планеты. Она не заменяет atlas и не является
плоской картинкой, закрывающей сферу.

---------------------------------------------------------------------
11.1. ХАРАКТЕР И РОЛЬ
---------------------------------------------------------------------

Планетка:

- добрая;
- любопытная;
- спокойная;
- немного игривая;
- не разговаривает свысока;
- не ведёт себя слишком младенчески для старших детей;
- помогает изучать литературу, а не отвлекает от неё;
- не подталкивает к покупкам;
- не стыдит за ошибку;
- не использует манипулятивные награды;
- не требует постоянной активности.

Она выступает проводником:

- приветствует ребёнка по выбранному локальному nickname, если он задан;
- объясняет вращение и масштабирование;
- показывает, где открыть страну;
- предлагает возрастно допустимый маршрут;
- знакомит с детским писателем;
- предлагает одно одобренное произведение;
- объясняет различие страны, автора и книги;
- напоминает о сохранении в любимое;
- помогает вернуться домой;
- мягко объясняет offline state;
- показывает короткие подтверждённые факты;
- сопровождает первый запуск нового скина/фона;
- может быть свёрнута одной доступной кнопкой.

В v1 запрещены:

- открытый AI-чат;
- непредсказуемые генеративные ответы;
- передача детских запросов внешней AI-службе;
- микрофонное распознавание;
- синтетическое клонирование голосов авторов;
- выдуманные цитаты;
- автоматические биографические факты.

Реплики Планетки хранятся в versioned GuideScript catalog, проходят
редакторскую проверку и могут иметь заранее записанный оригинальный или
лицензированный голос. Всегда показывать captions. Звук выключается.

---------------------------------------------------------------------
11.2. ВНЕШНИЙ ВИД
---------------------------------------------------------------------

Обязательный внешний вид базовой «Весёлой Планетки»:

- очень милый, но профессионально выполненный;
- доброжелательное лицо;
- высококачественная поверхность сферы;
- география остаётся узнаваемой;
- крупные выразительные глаза с аккуратными бликами;
- небольшие мягкие брови;
- лёгкие щёчки;
- рот заметно расположен ниже глаз;
- улыбка не перекрывает континенты сильнее необходимого;
- руки полностью находятся в safe composition area;
- ноги полностью находятся в safe composition area;
- аккуратные ладони/перчатки либо стилизованные кисти;
- устойчивые детские пропорции;
- никаких пугающих зубов, гиперреалистичной кожи и резкой мимики;
- никакого визуального сходства с чужим mascot без прав;
- качество не ниже готовой планеты сайта.

Face rig, eyes, brows, cheeks, mouth, arms, hands, legs, shoes и accessories
являются отдельными объектами. Их нельзя впекать в общую картографическую
текстуру. Это позволяет менять поверхность, сохраняя героя.

Создай MascotVariant system, чтобы разные детские скины могли менять:

- цвет и форму глаз;
- стиль щёк;
- форму улыбки;
- материал рук/ног;
- обувь;
- допустимые аксессуары;
- voice/caption personality preset;
- animation set;
- но сохраняли идентичность Планетки.

11.3. РЕЖИМЫ PLANETKA MODE И EXPLORE MODE
---------------------------------------------------------------------

Planetka Mode:

- герой полностью виден;
- подставка и выбранный фон участвуют в композиции;
- доступны greeting, hints и safe recommendations;
- globe может мягко покачиваться;
- управление не требует точного country picking.

Explore Mode:

- лицо/конечности мягко уменьшаются, отодвигаются или скрываются;
- не перекрывают важные области и labels;
- geography, UV, coordinates, picking и camera не меняются;
- активная тема сохраняется;
- Планетка остаётся компактным помощником в углу либо полностью скрывается
  по выбору;
- возврат в Planetka Mode обратим;
- reduced motion переключает без анимации.

Нельзя создавать вторую сферу для героя и вторую сферу для atlas, если это
приводит к расхождению географии. Использовать одну центральную sphere
foundation и presentation layers.

8-9 лет:

13-17 лет:

- optional companion;
- более нейтральный visual preset;
- подростковые child-safe/teen материалы;
- без инфантильной подачи.

11.6. OWNER-SUPPLIED ART И FALLBACK
---------------------------------------------------------------------

Если owner-approved 3D/model/texture assets Планетки уже существуют,
используй их как visual source of truth и не заменяй случайной генерацией.
Сделай техническую подготовку: topology audit, UV audit, rig, LOD,
materials, compression, animation clips и mobile profiling.

Если финальный 3D asset ещё не предоставлен:

- создай качественный modular runtime rig и documented import contract;
- используй оригинальный нейтральный development mascot, не копирующий
  чужих персонажей;
- production release нельзя считать визуально финальным с сырой
  programmer-art заглушкой;
- продолжай весь остальной функционал;
- зафиксируй только художественный asset approval как external owner
  blocker.

Каждый детский фон получает minAge/maxAge, motion tier и optional
sensitivity tags. Страшные, слишком тёмные или перегруженные эффекты не
показывать младшим профилям.

создавать lookalike. Codex реализует architecture/slots/validation, но
production content активируется только после rights-cleared assets.

Если license expires:

---------------------------------------------------------------------
18.6. СМЕНА ФОНА - UX И TRANSACTIONAL RUNTIME
---------------------------------------------------------------------

Пользовательский сценарий:

1. Открыть «Оформление».
2. Выбрать вкладку «Фоны».
3. Увидеть live-preview thumbnail/video-less interactive preview.
4. Нажать «Примерить».
5. Background manager загружает low tier.
6. Проверяет checksum/compatibility/memory.
7. Плавно crossfade меняет фон, свет и допустимый ambient sound.
8. Глобус, camera target и selected country не пересоздаются.
9. Пользователь применяет, покупает или отменяет.
10. При отмене возвращается точная предыдущая комбинация.
11. После покупки full tier догружается по policy.
12. Выбор сохраняется после restart.

Требования к transition:

- 350-700 ms по профилю сцены;
- reduced motion = мгновенная безопасная замена или короткий dissolve;
- без белого/чёрного кадра;
- без скачка exposure;
- без camera reset;
- без исчезновения selected state;
- old scene освобождается только после successful commit новой;
- при ошибке остаётся старая сцена;
- latest-request-wins;
- rapid A->B->C не коммитит B после C;
- audio crossfade отдельно и с mute policy;
- app background останавливает particles/audio;
- low-memory event может откатить 3D scene к 2.5D/static fallback.

---------------------------------------------------------------------
18.7. PERFORMANCE И ASSET PIPELINE ФОНОВ
---------------------------------------------------------------------

Используй подходящие форматы после проверки поддержки:

- GLB/GLTF;
- Meshopt/Draco только если runtime/лицензия/CPU cost оправданы;
- KTX2/Basis compressed textures;
- AVIF/WebP fallback;
- precomputed lightmaps там, где это выгодно;
- LOD;
- instancing;
- texture atlases без потери читаемости;
- occlusion/frustum culling;
- bounded asset cache.

Каждая сцена имеет budgets для Economy/Balanced/High. High и Balanced сохраняют полноценную 3D-геометрию; Economy может использовать 3D-lite и только при необходимости 2.5D/static fallback:

- max triangles;
- max draw calls;
- max materials;
- max texture memory;
- max active lights;
- max animated objects;
- no uncontrolled transparent overdraw;
- no permanent postprocessing chain на слабом устройстве.

Не держи одновременно в памяти все 3D-фоны. Preview thumbnails отдельно от
runtime assets. Store list не должен загружать полный GLB каждого товара.

======================================================================
21. СЕРВЕРНАЯ ПРОВЕРКА ПОКУПОК
======================================================================

Клиент не может сам выдать себе платный предмет.

Создай backend flow в существующей инфраструктуре:

- Apple verification;
- Google Play verification;
- RuStore verification;
- idempotent entitlement grant;
- transaction uniqueness;
- refund/revocation;
- retry queue;
- audit log;
- server timestamps;
- secrets only on server;
- webhooks/server notifications where available;
- reconciliation job;
- entitlement refresh;
- rate limiting;
- tamper-resistant catalog mapping.

Проверки:

- повторная transaction не дублирует entitlement;
- поддельный local flag не открывает item;
- revoked item закрывается после verified refresh;
- offline сохраняет последний verified snapshot;
- backend error не уничтожает данные, включённые в базовую покупку;
- receipts/tokens не логируются;
- purchase token не хранится в открытом виде без необходимости;
- client cannot choose arbitrary product mapping;
- environment/store mismatch fail-closed;
- test transactions не попадают в production entitlements.

Entitlements должны быть доступны guest-first. Для cross-device sync
допускается parent/adult account, но аккаунт не требуется ребёнку и не
блокирует первую версию.

22. ДЕТСКИЙ РЕЖИМ, ТОЧНЫЙ ВОЗРАСТ И AGE-GATED CONTENT ENGINE

Детский режим является отдельным policy-controlled experience. Он не
реализуется только CSS-классом или простым фильтром массива.

---------------------------------------------------------------------
22.1. СОЗДАНИЕ И ВЫБОР ПРОФИЛЯ
---------------------------------------------------------------------

Родитель:

- включает child mode;
- создаёт один или несколько локальных профилей;
- указывает точный возраст в полных годах 3-17;
- при желании задаёт nickname без настоящего имени;
- выбирает reading level;
- устанавливает PIN;
- выбирает allowed/blocked topics;
- включает/выключает магазин;
- включает/выключает external links;
- выбирает motion level;
- выбирает sound/narration;
- устанавливает мягкое time reminder;
- выбирает детскую тему, включённую в базовую покупку.

Возраст:

- изменяется только через Parent Gate;
- подтверждается минимум раз в 12 месяцев;
- не берётся из введённой ребёнком даты;
- не публикуется;
- не используется для рекламы;
- не отправляется сторонним analytics/AI providers;
- хранится локально/безопасно согласно data map;
- при corrupted/missing profile policy приложение fail-closed и просит
  взрослого восстановить настройки.

Child mode и выбранный профиль сохраняются после:

- restart;
- crash;
- app update;
- background/resume;
- process recreation;
- orientation change;
- content update;
- deep-link launch;
- store callback.

---------------------------------------------------------------------
22.2. AGE POLICY ДЛЯ ПРОИЗВЕДЕНИЙ
---------------------------------------------------------------------

Главное правило:

Возраст проверяется на уровне КАЖДОГО ПРОИЗВЕДЕНИЯ, а не только автора.

Пример:

- писатель имеет 20 works;
- 5 вручную approved for children;
- для профиля 6 лет подходят 2;
- child writer screen показывает только эти 2;
- остальные 18 не должны попасть даже в hidden metadata, search snippets,
  related links или offline payload конкретного age package.

Единый ChildContentPolicyService используется всеми слоями. Нельзя писать
локальную копию условий на каждом экране.

Policy получает:

- active profile;
- content record;
- rights status;
- current content version;
- parent blocked topics;
- route source;
- network/offline state;
- territory if needed only for rights, без точной геолокации;
- app version.

Policy возвращает typed decision:

- ALLOW;
- DENY_NOT_REVIEWED;
- DENY_AGE_TOO_LOW;
- DENY_AGE_TOO_HIGH;
- DENY_BLOCKED_TOPIC;
- DENY_RIGHTS;
- DENY_VERSION;
- DENY_MODE;
- DENY_CORRUPT_PROFILE;
- DENY_UNKNOWN_FAIL_CLOSED.

Ребёнку не показывать техническую причину или название запрещённого
adult work. Показывать нейтральное безопасное сообщение. Подробность
доступна только родителю в Parent Center/diagnostics.

22.3. ОТДЕЛЬНЫЕ AGE PACKAGES И ИНДЕКСЫ
---------------------------------------------------------------------

- child-writers-3-5;
- child-works-3-5;
- child-search-3-5;
- child-collections-3-5;

- child-writers-10-12;
- child-works-10-12;
- child-search-10-12;
- child-collections-10-12;
- child/teen packages 13-15 и 16-17 при наличии подтверждённого контента.

Можно использовать один encrypted/local database с row-level age policy,
если доказано тестами, что adult records не могут попасть в child query.
Но для offline bootstrap предпочтительны заранее отфильтрованные packages,
уменьшающие риск leakage.

При смене возраста родителем:

1. Parent Gate уже пройден.
2. Пересчитать age band.

7. Не показывать их названия ребёнку.
8. Обновить подборки Планетки.
9. Записать policy migration.
10. Проверить offline state.

23.1. ИЗМЕНЕНИЕ ВОЗРАСТА
---------------------------------------------------------------------

Изменение возраста:

- только после успешного Parent Gate;
- требует явного подтверждения;
- показывает, что набор доступных произведений может измениться;
- не просит полную дату рождения;
- не позволяет ребёнку перейти в adult mode;
- инвалидирует age-dependent cache;
- активирует новую версию child package;
- перефильтровывает favorites/history;
- сохраняет безопасный audit event без имени ребёнка;
- имеет rollback при неудачной загрузке нового package;
- при offline смене разрешает только уже установленный совместимый пакет,
  иначе откладывает activation и сохраняет прежнюю безопасную policy.

Возраст автоматически не увеличивать молча. Через 12 месяцев показать
родителю reminder подтвердить возраст. До подтверждения продолжать
последнюю безопасную policy, не расширять доступ автоматически.

---------------------------------------------------------------------
23.2. PIN И БИОМЕТРИЯ
---------------------------------------------------------------------

Выход из child mode, смена возраста, покупки, external links, удаление
данных и лицензированные пакеты проходят Parent Gate:

- PIN;
- optional system biometrics;
- rate limiting;
- progressive delay после ошибок;
- secure storage;
- PIN не логируется;
- Android Back не обходит;
- deep link не обходит;
- restart не обходит;
- route restoration не обходит;
- notification не обходит;
- store callback не обходит;
- accessibility action не обходит;
- debug shortcut отсутствует в production.

PIN recovery:

- безопасный;
- не создаёт hidden bypass;
- biometric/system owner confirmation where possible;
- при отсутствии recovery документировать reinstall behaviour;
- не отправлять PIN на сервер без необходимости;
- хранить verifier/hash с солью в secure storage;
- не хранить raw PIN в preferences/IndexedDB/logs;
- не использовать простые hardcoded master PIN.

---------------------------------------------------------------------

2. Проверить schema.
3. Проверить minimumAppVersion.
4. Скачать во temporary area.
5. Проверить checksum каждого файла.
6. Выполнить migration.
7. Атомарно переключить active version.
8. При ошибке оставить previous version.
9. Удалить temporary files.
10. Записать безопасный diagnostic.
11. Не активировать partial package.
12. Поддержать rollback на предыдущую verified version.

26A. WEB/PWA — ПЕРВАЯ ИЗ ТРЁХ ПЛАТФОРМ
======================================================================

Web/PWA является полноценным release target, а не browser demo.

После аудита существующего сайта выбери безопасную стратегию:

- отдельный apps/mobile/web или apps/web-pwa build на выделенном route;
- либо другой изолированный artifact, который не ломает текущие
  статические/SEO routes и existing service worker.

Обязательно:

- Web App Manifest;
- installable and maskable icons;
- standalone display;
- theme/background colors из бренда;
- controlled service-worker scope;
- offline bootstrap;
- cache versioning;
- atomic update/rollback;
- app-shell navigation;
- responsive phone/tablet/desktop;
- touch/mouse/keyboard;
- reduced motion;
- accessibility;
- canonical links на статьи сайта;
- no remote iframe;
- no second literary database;
- no second globe engine;
- production CSP;
- no eval/remote executable code;
- Lighthouse/Playwright evidence;
- install test Chromium/Android;
- Safari/iOS add-to-home-screen graceful behavior;
- conflict test с текущим site service worker.

Web store:

- included catalog, optional catalog, preview, install/apply и owned entitlements работают;
- entitlements, приобретённые на поддерживаемых платформах, отображаются
  после account/server reconciliation;
- WebPurchaseProvider создаётся как отдельный adapter;
- реальный checkout включается только при approved PSP, merchant account,
  legal pages, tax/territory policy и server verification;
- при отсутствии credentials checkout имеет честное unavailable state;
- нельзя делать fake purchase, собирать card data самостоятельно или
  использовать client-only unlock.

Web release artifacts:

- production bundle;
- manifest;
- service worker;
- deployment package;
- route/server configuration;
- integrity manifest;
- Lighthouse report;
- PWA install/offline E2E;
- documented rollback.

Definition of Done:

- PWA устанавливается;
- base globe и bootstrap открываются offline;
- update не ломает active version;
- service worker не перехватывает чужие routes;
- сайт сохраняет release/SEO tests;
- app использует canonical globe/content kernel;
- web checkout не симулируется в production.

30. ПРОИЗВОДИТЕЛЬНОСТЬ И НАДЁЖНОСТЬ
======================================================================

Сначала измерь фактический baseline на текущем проекте.

Целевые ориентиры:

- shell usable: 2.5-3.0 s на среднем устройстве после холодного запуска;
- globe interactive: до 4 s cold и до 1.5 s warm;
- 55-60 FPS на средних/сильных устройствах;
- стабильные 30 FPS в Economy;
- idle не рендерит постоянно без причины;
- skin switch не вызывает долгий freeze;
- отсутствует нарастающая память после 20 минут работы;
- отсутствует нарастающая память после 30 смен skins/stands/backgrounds;
- background/resume не создаёт второй renderer;
- app возвращается из low-memory state без повреждения данных.

Если текущий baseline отличается:

- измерь его;
- зафиксируй устройство и методику;
- установи обоснованный performance budget;
- не ухудшай показатели без документированной причины.

Graphics tiers:

High:
- high-resolution texture;
- atmosphere;
- мягкие дополнительные эффекты;
- полноценный оптимизированный background.

Balanced:
- mobile 2K texture;
- ограниченные эффекты;
- оптимизированный background;
- основной рекомендуемый tier.

Economy:
- 1K/2K texture;
- минимальная atmosphere;
- demand render loop;
- статичный/лёгкий background;
- сниженная animation;
- меньшая anisotropy;
- агрессивное освобождение неиспользуемых assets.

Обязательные оптимизации:

- dynamic imports;
- lazy screens;
- responsive texture selection;
- platform-safe texture compression;
- bounded asset cache;
- explicit texture/material/geometry disposal;
- visibility/offscreen suspension;
- app background suspension;
- один Canvas;
- один renderer;
- no mass preload store assets;
- no React state update per frame;
- debounce/coalescing pointer events;
- latest-request-wins;
- cancel stale downloads;
- pause prefetch при interaction;
- profile before optimization;
- performance regression tests;
- bundle size budget;
- content package size budget.

Надёжность:

- error boundaries не скрывают критические ошибки;
- app не остаётся на бесконечном loader;
- каждый recoverable error имеет Retry;
- network timeout ограничен;
- stale request отменяется;
- interrupted content update откатывается;
- corrupted local DB проходит repair/rollback path;
- purchase callback после restart обрабатывается;
- lifecycle listeners очищаются;
- никаких duplicate subscriptions после remount.
