# OWNER OPERATIONS AND MAINTENANCE MANUAL REQUIREMENTS — V12

Codex must generate a final manual matching the implemented product.

## Daily / event-driven

- review health/critical alerts;
- handle P0/P1 incidents;
- check purchase verification outage;
- react to rights/takedown notice;
- inspect failed content publish;
- support escalations.

## Weekly

- backup status;
- failed update/download trends;
- store reconciliation;
- open security advisories;
- support categories;
- upcoming license expiries;
- CI health.

## Monthly

- restore drill sample;
- dependency and store-policy review;
- performance/error review by device tier;
- content correction queue;
- child review queue;
- SKU/territory audit;
- store listing accuracy;
- storage/CDN cost review.

## Quarterly

- full restore drill;
- threat model review;
- privacy/data retention audit;
- accessibility regression;
- supported OS/device review;
- licensed content audit;
- unit economics and price review;
- incident tabletop;
- disaster recovery exercise;
- operations access review.

## Annually / major release

- SDK/API/store requirements;
- Paid Apps/merchant/tax agreements;
- age rating and privacy declarations;
- legal drafts;
- child policy and age assurance;
- rights/licensing renewal;
- EOL/deprecation plan;
- backup retention;
- app/PWA architecture review;
- full device matrix;
- owner account recovery test.

## Standard owner procedures

Manual must contain exact UI/CLI steps for:

- publish/correct writer/work;
- approve child biography/work;
- create journey;
- edit Planetka script;
- add skin/stand/background/accessory;
- create included/optional bundle;
- map store SKU;
- update price planning/territory;
- add licensed pack;
- upload approved assets;
- publish/rollback content;
- stage app release;
- restore purchases/reconcile;
- delist licensed content;
- generate store screenshots/metadata;
- backup/restore;
- export diagnostic;
- respond to incident/rejection;
- rotate secrets;
- deprecate old version.

Each procedure states role, prerequisites, dry-run, action, validation,
rollback and audit evidence.
