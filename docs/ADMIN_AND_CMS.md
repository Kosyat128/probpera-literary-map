# Редакционная система «Проба Пера»

## Что уже предусмотрено

- защищённый кабинет по адресу `https://admin.probpera.ru`;
- отдельные роли `owner`, `admin`, `editor`, не связанные с ролью обычного читателя;
- визуальный редактор статей с резервной копией в браузере;
- статусы: черновик, проверка, расписание, публикация, скрытие, архив;
- автоматическая история предыдущих версий и журнал действий;
- рубрики и теги;
- медиатека с обязательным alt-текстом, источником и лицензией;
- собственная модерация комментариев и собственная статистика;
- управление главной страницей, страницами, баннерами и меню;
- прямой визуальный режим: страница сайта открывается внутри кабинета, а клик
  по тексту, писателю или книге выбирает связанное поле для редактирования;
- постоянные CMS-замены писателей и произведений поверх проверенных исходников,
  с историей ревизий и защитой от перезаписи последующей синхронизацией;
- SEO-поля, канонический адрес и постоянные 301-редиректы.

## Первичное подключение

1. Создать резервную копию текущего проекта Supabase.
2. Применить базовую схему `supabase/schema.sql`, миграцию безопасности
   `supabase/migrations/20260727_community_safety.sql`, затем
   `supabase/migrations/20260728_cms_foundation.sql`,
   `supabase/migrations/20260728_reader_favorites.sql`,
   `supabase/migrations/20260730_literary_archive.sql`,
   `supabase/migrations/20260730_page_revision_history.sql` и
   `supabase/migrations/20260730_staff_management.sql`, затем миграции
   `20260801_forum_reports.sql`, `20260801_reader_profiles_and_forum_votes.sql`,
   `20260802_client_errors.sql`, `20260802_editor_templates.sql`,
   `20260802_reader_journey.sql` и
   `20260803_public_article_view_counts.sql`,
   `20260808_article_translations.sql` и
   `20260808_book_translations_and_import_staging.sql`, затем
   `20260812_homepage_block_revisions.sql` и
   `20260812_writer_and_work_revisions.sql`, затем
   `20260813_editorial_database_admin.sql`,
   `20260813_homepage_atomic_move.sql`,
   `20260813_tags_updated_at.sql` и
   `20260813_unified_revision_history.sql` в порядке имени файла.
3. Скопировать `apps/admin/.env.example` в локальный `.env.local` панели и
   заполнить публичные параметры Supabase. Ключ `service_role` нельзя добавлять
   в переменные `NEXT_PUBLIC_*` и нельзя передавать браузеру.
4. Зарегистрировать владельца через Supabase Auth, затем один раз назначить его:

   ```sql
   insert into public.staff_memberships (user_id, role)
   select id, 'owner'
   from auth.users
   where email = 'ваша-почта';
   ```

5. Для ежедневной редакционной работы выполнить `npm run admin:serve` (команда сама
   собирает панель и запускает её). Это стабильный production-режим без служебных worker-процессов
   Next.js, из-за которых Windows мог показывать экран `Jest worker encountered ...`.
   Команда `npm run admin:dev` оставлена только для разработки исходного кода панели.
   При значении `ADMIN_BASE_PATH=/` локальный
   адрес: `http://localhost:3000`. Если панель намеренно запускается под
   префиксом `/admin`, задайте `ADMIN_BASE_PATH=/admin` до сборки.

## Как войти владельцу

1. В Supabase открыть **Authentication → Users** и создать пользователя с
   подтверждённой электронной почтой и надёжным паролем.
2. В **SQL Editor** выполнить запрос назначения роли `owner`, приведённый выше,
   подставив точную почту созданного пользователя.
3. В настройках Auth добавить `https://admin.probpera.ru` как Site URL и
   `https://admin.probpera.ru/login` в список разрешённых redirect URL.
4. Открыть `https://admin.probpera.ru/login`, ввести ту же почту и пароль.
5. После входа открыть **Настройки → Команда редакции**. Только владелец может
   выдавать и отзывать роли `owner`, `admin` и `editor`.

Обычная регистрация читателя не даёт доступа в редакцию. Ключ
`service_role` панели для входа, публикации и загрузки медиа не требуется:
доступ обеспечивают сессия пользователя, отдельная роль и RLS-политики.

## Перенос существующих статей

Сначала выполняется только проверка:

```text
npm run content:import:cms
```

Для настоящего импорта нужны только серверные переменные
`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `CMS_OWNER_USER_ID`.
После резервной копии запускать:

```text
node scripts/import-articles-to-supabase.mjs --apply
```

Импорт не меняет тексты и заголовки. Старый адрес записывается в `legacy_path`,
новый понятный адрес создаётся отдельно. Папка `src/data/countries` остаётся
единственным главным источником стран, писателей и литературной энциклопедии.
В ней хранится архив из 4000 карточек. Автоматически собранные 2356 записей
имеют статус `draft` и не показываются читателям до ручной проверки имени,
страны, биографии, произведений, источников и прав на портрет.

## Прямое редактирование сайта

Раздел **Главная страница → Прямое редактирование** открывает живой сайт в
защищённом окне. Обычный клик выбирает текст или связанную сущность;
`Ctrl`/`⌘` + клик переходит по внутренней ссылке, а `Shift`/`Alt` + клик временно включает
обычное управление глобусом, слайдером или аккордеоном.

Короткие подписи сохраняются в едином словаре интерфейса. Блоки главной,
страницы, меню, баннеры, статьи, писатели и книги сохраняются в собственных
CMS-таблицах. После сохранения создаётся запись истории и запускается публичная
сборка. Статические исходники остаются резервной копией, но опубликованная
правка владельца накладывается последней и не стирается при обновлении кода.

Для блока главной визуальный инспектор отдельно настраивает изображение и текст.
У изображения доступны режим заполнения (`cover`, `contain`, `fill`), девять
безопасных точек фокуса, масштаб 50–200%, затемнение 0–90%, яркость, контраст и
насыщенность 0–200%, размытие 0–20 px. Для заголовка доступны размер 20–112 px,
выравнивание, начертание и межстрочный интервал 0,8–1,6; для описания — размер
12–32 px и интервал 1–2,2. Изменения сразу видны в защищённом предпросмотре.

Кнопка **Сбросить оформление** удаляет только эти параметры из настроек блока и
возвращает фирменные стили сайта; тексты, ссылки и выбранное изображение остаются
на месте. Сервер принимает только фиксированный список значений и числовые
диапазоны — произвольный CSS, HTML или JSON через визуальный инспектор сохранить
нельзя.

Пустое поле быстрого редактора писателя удаляет соответствующее редакционное
переопределение, а не записывает пустую строку поверх проверенной исходной
карточки.

В **Книжном архиве** кнопка **Редактировать** у существующего точного издания
открывает ISBN, издателя, год, язык, формат, число страниц, обложку и полный
контур её происхождения и прав. Хотя бы один ISBN проходит контрольную проверку;
обложка не сохраняется без HTTPS-источника, подтверждённого статуса прав и даты
проверки. Каждая правка попадает в `book_edition_revisions`, журнал аудита и
немедленно ставит публичную сборку в очередь.

Раздел **История изменений** также показывает версии баннеров и пунктов меню из
`site_chrome_revisions`. При восстановлении сервер сверяет тип сущности и
переносит только фиксированный список колонок; идентификаторы, даты создания и
владелец записи из старого снимка не восстанавливаются. Удалённый исходный
объект автоматически не пересоздаётся — кабинет сообщает об этом вместо ложного
успеха.

Публичный сайт разрешает iframe только точному origin
`https://admin.probpera.ru`; wildcard и сторонние домены запрещены политикой
`frame-ancestors`.

## Изображения

Портреты не генерируются. В медиатеке хранятся:

- имя автора изображения;
- исходная страница;
- название и ссылка лицензии;
- подпись;
- alt-текст;
- коллекция.

SVG сознательно не загружается: активное содержимое в SVG создаёт лишний риск.
JPEG, PNG, WebP и AVIF очищаются от метаданных, уменьшаются до 2400 px и
публикуются в WebP.

## Как подготовить новую статью

1. Откройте **Статьи → Новая статья**, найдите похожий материал и нажмите
   **Создать копию и редактировать**. Заголовки разделов, блоки, старые
   изображения, подписи и их расположение сохранятся; исходная статья не
   изменится.
2. Замените заголовок и подготовленный текст своим материалом. Адрес статьи
   создаётся из нового заголовка автоматически; вручную менять его обычно не
   требуется.
3. Чтобы заменить старую иллюстрацию, щёлкните прямо по ней и нажмите
   **Заменить изображение**. Выберите файл с компьютера — новая картинка займёт
   то же место и сохранит режим размещения без обрезки и растягивания.
4. Под выбранной иллюстрацией доступны alt-текст, подпись и четыре режима:
   **Широко**, **По центру**, **Слева**, **Справа**. На телефоне боковые
   варианты автоматически становятся полноширинными.
5. Если статья создаётся без старого образца, выберите одну из готовых
   структур. В квадратных местах для иллюстраций нажмите **Выбрать
   изображение** или перетащите файл прямо в квадрат.
6. Основные действия с текстом оставлены на панели постоянно. Дополнительные
   блоки, фотографии, галереи, слайдеры и редкие настройки собраны в меню
   **＋ Блок**, **Фото и галереи** и **Ещё**, чтобы редактор не был перегружен.
7. Для нескольких иллюстраций используйте **Галерея** либо **Слайдер**.
   Встроенное окно принимает до восьми HTTPS-адресов, по одному в строке.
8. Перед публикацией проверьте предпросмотр, заголовок, рубрику, краткое
   описание, обложку, alt-тексты, источники, мобильное отображение и SEO-поля.
   Сначала сохраните черновик, затем назначьте публикацию или расписание.

## Публикация

При статусе «Опубликована» кабинет может вызвать
`PUBLIC_SITE_DEPLOY_HOOK_URL`. Публичная сборка получает только опубликованные
материалы через RLS. Черновики и редакционные данные анонимному пользователю
недоступны.

Перед выпуском:

```text
npm run build:all
npm run test
npm run links:audit
```
