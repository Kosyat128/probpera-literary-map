# SEO и точная аналитика «Пробы Пера»

## Что работает в коде

- Главная и каждая индексируемая публикация имеют самостоятельные `title`,
  description, canonical, Open Graph, Twitter Card и JSON-LD.
- Статический HTML главной содержит описание проекта, основные разделы и ссылки
  на свежие публикации: важный контент доступен роботу без выполнения JavaScript.
- `sitemap.xml` включает только индексируемые canonical URL. `lastmod` берётся из
  даты публикации/изменения материала, а не подменяется датой каждой сборки.
- `robots.txt` указывает sitemap и удаляет только известные рекламные параметры
  (`utm_*`, `yclid`, `gclid`, `fbclid`), не затрагивая рабочие фильтры сайта.
- Отдельный release-аудит проверяет sitemap, robots, canonical, метаданные,
  JSON-LD, статический текст и отсутствие Метрики до согласия.

## Контракт Яндекс Метрики

Единственный публичный идентификатор конфигурации:

```text
YANDEX_METRIKA_COUNTER_ID=<цифровой номер счётчика>
```

Это не секрет. Значение должно быть переменной репозитория/окружения и
передаваться шагу production-сборки. Пустое значение отключает интеграцию;
некорректное непустое значение останавливает сборку. Номер нельзя придумывать:
его берут только из счётчика, созданного владельцем домена `probpera.ru`.

Счётчик использует SPA-схему `defer + hit`: один просмотр отправляется при
первом открытии и при реальном изменении URL. Повторные события одного URL не
раздувают статистику. Предпросмотр из админки исключён. Вебвизор и карта кликов
отключены; переходы по ссылкам и точный показатель отказов включены.

## Согласие и минимизация данных

До явного выбора посетителя код Метрики и `noscript`-пиксель не загружаются.
Выбор хранится в `localStorage` под ключом
`probpera-analytics-consent-v1` (`granted` или `denied`). Для интеграции с
внешним CMP предусмотрено событие `probpera:analytics-consent-changed` с
`detail.analytics = "granted" | "denied"`. При отказе/отзыве новые хиты
останавливаются; компактная кнопка настроек позволяет посетителю изменить выбор
в любое время. Собственный счётчик просмотров подчиняется тому же выбору и при
отказе не отправляет записи в Supabase. Для авторизованного посетителя запись
может содержать ID его аккаунта, а для остальных — случайный ID сессии; этот
счётчик не заявляет географию, которой у него нет.

## Страны и регионы без выдуманных данных

Точная география берётся из стандартного отчёта Яндекс Метрики
`Отчёты → Аудитория → География`: страна, область/регион и город (если сервис
может его определить). Клиентские язык и часовой пояс не подменяются «страной».
РФ и остальные страны сравниваются в одном отчёте по посетителям, визитам,
просмотрам и отказам. Низкие объёмы могут агрегироваться самим сервисом ради
обезличивания.

В админке раздел `Статистика` даёт прямой переход в отчёт
`Аудитория → География` именно настроенного production-счётчика. Если ID не
передан сборке админки, ссылка безопасно ведёт к списку доступных счётчиков и не
подставляет случайный номер.

Для вывода этих агрегатов прямо в собственной админке позднее потребуется
OAuth-доступ к API отчётов Метрики. OAuth-токен является секретом; без
доказанного доступа код не создаёт фиктивные страны и не подставляет тестовые
значения.

## Что требует действия владельца внешнего сервиса

1. Создать или выбрать ровно один счётчик для `https://probpera.ru` в аккаунте
   Яндекс Метрики и получить его цифровой ID.
2. Сохранить ID как `YANDEX_METRIKA_COUNTER_ID` и передать его production-build.
3. В Яндекс Вебмастере подтвердить домен и отправить
   `https://probpera.ru/sitemap.xml`. Это действие невозможно выполнить без
   авторизованного аккаунта владельца.
4. После выпуска проверить один визит в инкогнито и отчёт «География»; фильтр
   «Не учитывать мои визиты» не должен использоваться для контрольного визита.

Техническая оптимизация устраняет препятствия индексации, но ни один корректный
инструмент не может гарантировать конкретную позицию в поисковой выдаче.
