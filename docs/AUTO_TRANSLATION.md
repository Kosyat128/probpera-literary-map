# Премиальный автоматический английский перевод

## Архитектура качества

Премиальный EN-контур использует два независимых серверных прохода OpenAI Responses API:

1. `GPT-5.6 Sol` выступает как старший литературный переводчик и создаёт структурированный английский черновик.
2. Второй `GPT-5.6 Sol` получает одновременно русский исходник и черновик, сверяет их и возвращает финальную редактуру на естественном литературном английском.

Второй проход включён по умолчанию. Он исправляет буквальные кальки, синтаксис, терминологию и стилистику, но не имеет права добавлять новые факты, даты, источники или интерпретации.

Все запросы отправляются с `store: false`, а `OPENAI_API_KEY` используется только серверной админкой. Полные исходные тексты и ключ API не пишутся в `admin_audit_log`.

## Статьи

Когда русская статья публикуется, сервер перед публичной сборкой проверяет английскую версию.

- Если опубликованный EN уже соответствует текущему `source_content_hash`, платный запрос не выполняется.
- Если EN отсутствует или русский исходник изменился, выполняются перевод и отдельный editorial review.
- Результат проходит строгую JSON-схему, санитаризацию и существующие editorial release-checks.
- Порядок и вложенность HTML должны сохраниться.
- `href`, `src`, `id`, `class`, служебные `data-*` и другие защищённые атрибуты должны остаться неизменными.
- Модель не может создавать или удалять ссылки и изображения.
- Библиография и источники переводятся без права придумывать даты, ISBN, издателей, URL или другие данные.
- Конфликт версии прекращает запись и не перетирает более свежую правку.

Для уже опубликованного архива в админке есть **Premium English** → пакет статей. Пакет намеренно мал: длинные статьи требуют двух модельных проходов и не должны упираться в лимиты Worker.

## Книжный архив

Для `literary_work_translations` добавлен честный метод `machine-translation`.

Автоматический EN создаётся только когда:

- сама карточка произведения имеет статус `reviewed` или `verified`;
- русская языковая карточка имеет статус `reviewed` или `verified`;
- у русского текста есть `source_urls`;
- отсутствует принятый ручной английский перевод либо существующий EN ранее был создан тем же машинным pipeline.

Ручной `reviewed/verified` EN никогда автоматически не заменяется. Машинный EN хранит source hash, модели, request IDs и время генерации в `metadata.premiumTranslation`. Перед записью русский `updated_at` проверяется повторно.

Новая DB-миграция предоставляет `premium_machine_translation_ready()`. Поэтому код может быть опубликован раньше миграции: до защищённого reconciliation автоматический книжный EN возвращает `not-ready`, а обычное сохранение книги продолжает работать.

## Биографии писателей

Автоматический перевод биографии разрешён только из `biographyTranslations.ru`, если это:

- `editorial-original`;
- статус `reviewed` или `verified`;
- есть дата проверки;
- есть полноценный provenance источников.

Legacy-поля `bio`, `biography` и `description` не становятся источником автоматической публикации, потому что сами по себе не доказывают происхождение текста и права на него. Лицензированный сторонний текст также не переводится автоматически без отдельного правового решения.

Машинная биография сохраняется как `method: machine-translation`, `translatedFromLocale: ru`, `sourceTextRights: project-original`, с source hash и модельным provenance. Ручной проверенный EN имеет приоритет.

## Системные тексты сайта

Редактор **«Тексты сайта»** автоматически переводит изменённый русский CMS-текст, если английское поле пустое или ранее принадлежало машинному pipeline.

Если редактор вручную изменяет EN, поле немедленно становится human-owned и больше не перезаписывается автоматически. Для уже существующих русских CMS-переопределений есть пакетный backfill в разделе **Premium English**.

Короткие UI-строки переводятся пакетами по строгой схеме: ключи и их порядок не могут измениться.

## Translation Center

Раздел админки **Premium English** показывает:

- активную модель переводчика и модель второго редакторского прохода;
- наличие server-side `OPENAI_API_KEY`;
- готовность книжной DB-схемы;
- количество опубликованных статей и EN-версий;
- количество проверенных RU/EN книжных карточек;
- число биографий, которые имеют безопасный редакционный RU-источник;
- число CMS site-copy overrides и машинных EN.

Из центра можно безопасно запускать небольшие пакеты статей, книг, биографий и site-copy. После фактических изменений создаётся один обычный public build request.

## Переменные окружения

Серверный секрет:

```text
OPENAI_API_KEY=<secret>
```

Ключ нельзя объявлять с префиксом `NEXT_PUBLIC_` или `VITE_`.

Параметры premium-режима:

```text
OPENAI_TRANSLATION_MODEL=gpt-5.6-sol
OPENAI_TRANSLATION_REVIEW_MODEL=gpt-5.6-sol
OPENAI_PREMIUM_TRANSLATION_REVIEW=true
OPENAI_AUTO_TRANSLATE_ARTICLES=true
OPENAI_AUTO_TRANSLATE_LIBRARY=true
OPENAI_AUTO_TRANSLATE_SITE_COPY=true
OPENAI_AUTO_TRANSLATE_PROFILES=true
```

Отключение `OPENAI_PREMIUM_TRANSLATION_REVIEW` оставляет один переводной проход и снижает расход токенов, но это уже не полный premium-режим.

## Cloudflare Production

Редакционная панель работает в Worker `probpera-admin`. В Cloudflare Dashboard откройте Worker → **Settings → Variables and Secrets** и добавьте `OPENAI_API_KEY` именно как **Secret**.

Остальные `OPENAI_*` можно оставить отсутствующими: код использует значения по умолчанию выше. В `apps/admin/wrangler.jsonc` включён `keep_vars: true`, поэтому последующие deploy сохраняют Worker Variables и Secrets.

## Аудит и расходы

Успешные машинные операции фиксируют модель, reviewer model, request IDs, source hash, количество токенов и длительность, но не полный текст и не API key.

Premium-режим выполняет два модельных запроса вместо одного, поэтому расход API выше. Повторные запросы исключаются source hash там, где контент уже актуален; ручные английские версии не перегенерируются без необходимости.
