# Автоматический английский перевод статей

## Что происходит при публикации

Когда русская статья получает статус `published`, сервер админки перед запуском публичной сборки проверяет английскую версию.

- Если английская версия уже опубликована и её `source_content_hash` совпадает с текущим русским исходником, запрос к AI не выполняется.
- Если английской версии нет или русский исходник изменился, сервер переводит статью через OpenAI Responses API.
- Перевод сохраняется в `article_translations` с `locale = 'en'`, `status = 'published'` и хэшем текущего русского исходника.
- После успешного сохранения запускается обычная публичная сборка, поэтому русский и актуальный английский материал могут попасть в один выпуск.
- Если во время перевода русский исходник или английская версия меняются в другой вкладке, автоматическая запись прекращается как конфликт и не перетирает более свежую правку.
- Ошибка AI не удаляет уже принятую русскую публикацию. Событие фиксируется в `admin_audit_log` как `article.auto_translation.failed`, а следующий повтор публикации безопасно попробует снова.

## Качество и защита структуры

Серверный промпт требует литературный, естественный английский без добавления новых фактов. Результат возвращается по строгой JSON-схеме.

Перед записью выполняются дополнительные проверки:

- HTML проходит санитаризацию;
- порядок и вложенность HTML-элементов должны сохраниться;
- `href`, `src`, `id`, `class`, служебные `data-*` и другие защищённые атрибуты должны остаться неизменными;
- модель не может создавать или удалять ссылки и изображения;
- английская версия должна пройти редакционные release-checks: объём, H2, описание карточки, SEO, источники и отсутствие кириллицы;
- библиография и источники переводятся без права придумывать даты, ISBN, издателей, URL или другие библиографические данные.

## Секреты и настройки

В окружении **серверной админки** нужно задать:

```text
OPENAI_API_KEY=<секретный API key>
```

Ключ нельзя объявлять с префиксом `NEXT_PUBLIC_` или `VITE_`: он не должен попадать в браузерный bundle.

Дополнительные параметры:

```text
OPENAI_TRANSLATION_MODEL=gpt-5.6-sol
OPENAI_AUTO_TRANSLATE_ARTICLES=true
```

`gpt-5.6-sol` используется по умолчанию для максимального качества литературного перевода. Модель можно заменить серверной переменной окружения без изменения кода. Установка `OPENAI_AUTO_TRANSLATE_ARTICLES=false` полностью отключает автоматические переводы.

## Аудит

Успешный перевод создаёт событие `article.auto_translation.succeeded` с моделью, request id, source hash, количеством входных/выходных токенов и длительностью. Полный текст статьи и API key в журнал не записываются.
