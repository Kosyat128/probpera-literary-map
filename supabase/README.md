# Серверная часть сообщества «Проба Пера»

Интерфейс регистрации, форума, комментариев, рейтингов, просмотров и панели
редакции уже встроен в сайт. Для общей работы пользователей GitHub Pages
нужна одна серверная база проекта. Клиент использует только публичный ключ;
служебный ключ Supabase никогда не должен попадать в Vite или GitHub Pages.

## Первичное подключение

1. Создайте проект Supabase.
2. Откройте SQL Editor и целиком выполните файл `schema.sql`.
3. В настройках Authentication добавьте адрес сайта:
   `https://kosyat128.github.io/probpera-literary-map/`.
4. Для локального запуска скопируйте `.env.example` в `.env.local` и укажите:

```text
VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=ВАШ-ПУБЛИЧНЫЙ-ANON-KEY
```

5. В GitHub откройте `Settings → Secrets and variables → Actions → Secrets`
   и создайте секреты с теми же именами:
   `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
6. При необходимости добавьте обычную Actions Variable
   `VITE_BOOSTY_URL` с точным адресом страницы Boosty.

Следующий push в `main` соберёт сайт уже с подключённым сообществом.

## Назначение владельца редактором

Сначала зарегистрируйтесь на сайте, затем выполните в SQL Editor:

```sql
update public.profiles
set role = 'admin'
where id = (
  select id
  from auth.users
  where email = 'ВАША-ПОЧТА'
);
```

После повторного входа в панели сообщества появится закрытая вкладка редакции
со статистикой и очередью модерации.

## Что разрешено посетителям

- читать опубликованные темы и ответы;
- комментировать материалы без регистрации, указав имя;
- ставить рейтинг книгам и публикациям без регистрации;
- зарегистрироваться для постоянного профиля и участия в форуме.

Повторная анонимная оценка определяется локальным идентификатором браузерной
сессии. Политики RLS из `schema.sql` не дают посетителям доступа к закрытой
статистике и редакторским операциям.
