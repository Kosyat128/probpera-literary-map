# Independent review: CodeQL alerts 289, 290 and 291

Verdict for the three reviewed sinks: **intended non-executable data storage; no file-write vulnerability identified**. The network-to-file data flow is real, but it is the documented purpose of these collectors and diagnostics. A narrowly justified false-positive disposition for the vulnerability interpretation is reasonable after the current hardening is included in the reviewed commit. No alert was suppressed or dismissed by this review.

The official [CodeQL query documentation](https://codeql.github.com/codeql-query-help/javascript/js-http-to-file-access/) labels this query medium precision and asks reviewers to inspect the purpose of the write. Its concern includes remote content later being trusted as executable local content. This review traced each destination and relevant consumer rather than treating every JSON download as a vulnerability.

| Alert | Reviewed sink | Concrete reason |
| --- | --- | --- |
| 289 | `probe-literary-news-source-candidates.mjs`: scratch JSON | The destination is the fixed `.tmp/r10-source-research` directory plus a checked source ID and `.json`. `checkedProbeSourceId` accepts only 1-100 lowercase alphanumeric/hyphen characters, excluding path separators and traversal. The fetch is limited to 2 MiB per response. URL, content type and response text are serialized as JSON; repair reads use `JSON.parse` and inert Cheerio parsing. No file is imported, executed or written to a public web root. |
| 290 | Same script: source-evidence report JSON | The destination is fixed `reports/r10/sources` plus the same checked ID and `.json`. A finite candidate batch produces response hashes, parsed article facts and at most 100 discovered items. Report strings are JSON data. Code-owned/escaped patterns now prevent a replayed report from supplying an arbitrary regex to the probe parser. Later source-profile promotion is an explicit generator step; serialization quotes data and promoted profiles declare `autoPublication:false`. The report itself does not grant publishing rights. |
| 291 | `sync-literary-news.mjs`: `nobel-profile-check.json` | The filename is a literal under repository-resolved `.tmp/literary-news-sync`, with no network-controlled path component. The source is a fixed official Nobel HTTPS endpoint, redirects are refused, response type is checked and the body is limited to 256 KiB. The approved profile is schema-validated; the diagnostic also intentionally retains the bounded raw public JSON and its hash as evidence. It is uploaded as a JSON CI artifact with 14-day retention, not loaded as code or used as a script path. |

This verdict covers these file sinks only. The surrounding Nobel synchronization does write a separately validated approved profile to KV; this report does not describe the entire sync operation as read-only or authorize running it. Source-fetch SSRF, regex/property injection and unrelated alerts are outside this narrow disposition; their independent fixes still require their own validation. No provider calls, sync command or production writes were performed during this review.

The JSON companion records inspected file hashes and sink locations. Recheck those fingerprints if the implementation changes before disposition. Trusted checkout/local filesystem assumptions apply; this is not a proof against a local attacker who can replace the scripts or plant symlinks in the workspace.

The calendar governance delta was also compared structurally with Git HEAD: all existing projection fragments, allowed projection paths, baseline commit and metadata are unchanged. Only the owned `writerDatePatches.ts` addition hash changed and the exact supplemental JSON addition was appended; the original 60-data hash is unchanged. The self-pin test updates only the packet digest and exact addition-path list. No broad exemption was introduced. The parent reports 50 focused tests passing; this independent review did not rerun that suite.
