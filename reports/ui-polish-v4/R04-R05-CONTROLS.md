### Сенсорная кнопка и условия мобильной проверки

Завершённый общий целевой прогон: **56 passed / 14 failed / 8 skipped**, `owner-revision-e2e.log`. Этот результат не является общей приёмкой. Разбор трёх дополнительных mobile failures установил разные причины:

- **Настоящий R05 дефект:** при выборе страны и ширине320px старая нижняя привязка `.globe-touch-activation` помещала её прямо поверх двухрядного zoom/actions dock. Обычный click `zoom-in` блокировался120s. Прежние узкие layout probes использовали desktop context и этой сенсорной кнопки не имели; их результаты недостаточны для coarse-touch приёмки. Кнопка перенесена в отдельный ряд под изданиями во встроенной мобильной сцене. Новый постоянный R05 mobile regression требует существования настоящей touch-кнопки, высоты≥44px, границ внутри сцены и отсутствия пересечений с dock/изданиями/верхними actions, затем нажимает zoom без предварительного включения touch-mode.
- **Устаревший optical-centre контракт:** после корректного keyboard выбора страны Canvas сохранил identity/ширину/выбранную страну, но mobile stage законно вырос880→1000px. Старое требование неизменной высоты получило120px. Проверка теперь требует соответствия Canvas реальному stage до/после, прежнюю identity/selection/ширину и отсутствие уменьшения мобильной высоты. Desktop по-прежнему требует прежнюю высоту. Camera/model code не менялся.
- **Разные условия Indonesia pixel captures:** перед первым снимком Canvas374×998 имел top−79.5, перед вторым top−680.5 при том же viewport412×839. Режим rendering изменился demand→never/offscreen; camera idle, intent и revision8, странаIndonesia сохранились. Это подтверждённое отличие условий двух oversized `canvas.screenshot`, а не доказанное вращение камеры. Исправление стабильного pixel-capture теста ведёт reader agent, без изменения порога0.9 или времени ожидания.
