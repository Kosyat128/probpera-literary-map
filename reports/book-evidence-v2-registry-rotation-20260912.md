# Evidence V2 registry transition, 2026-09-12

Approved scope: seven additive source authorities; the validator and all historical migration/checksum pins stay unchanged. Canonical UTF-8 registry identity moves from `d0428d265845b68d6d5ee2ad9828353c91456eb5e57baf0f639702b8656044ef` to `c8d2b6862c47c3215295951d2c5d1c406913b9879c616f1d8b787c6e05029f6c`. The old Windows file-byte hash is not the database identity.

The existing service-role atomic archive commit is the only publication path. A forward migration changes the default for new controls and installs an exact transition capability; it does not rotate the live singleton. The unchanged guarded reconciliation workflow first backs up production, restores and reconciles an isolated copy, verifies the plan and main revision, and then invokes the existing archive release.

The commit retains its lock order, staged manifests, live snapshot checks, CMS preservation, idempotent receipt, and enforcement checks. At the rotation boundary it requires the exact old/new identities, every prior-public key, fresh staged evidence for every prior-public unlocked work, and checksum-bound attestation-only proofs rebuilt from the exact live CMS content. Only then can the same transaction switch the active registry and re-attest those CMS works. All retained predecessors must remain public and attested before commit. Any failure rolls back the registry, data, and proofs together; enforcement is never disabled.

CMS content, locks, original review dates, and review identities are preserved. Local overlays cannot repair or substitute a CMS snapshot. An unknown registry, changed snapshot, missing old-public work, invalid current proof, or a failed unchanged validator stops publication. Wells remains a production dependency until the owner's separate exact snapshot/metadata review is complete; this report does not claim it is ready.

Operational rollback is the existing verified encrypted backup/restore procedure. There is no separate registry downgrade RPC or unguarded production SQL step. A failed atomic commit needs no restore: its previous identity and attestations remain intact. A committed retry returns the existing receipt without rotating twice.
