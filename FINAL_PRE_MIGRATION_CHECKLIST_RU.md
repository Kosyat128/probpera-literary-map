# Финальная готовность «Пробы Пера» к переносу

Этот документ используется непосредственно перед переключением `probpera.ru`.
Обычная публикация на GitHub Pages не меняет DNS и не переносит домен.

## 1. Автоматическая проверка релиза

```text
npm ci
npm run release:check
npm run build:domain
```

`build:domain` создаёт в `dist` отдельный пакет для корня
`https://probpera.ru/`, добавляет `CNAME`, `.nojekyll`, sitemap, RSS,
manifest, страницу 404, HTML-переходы со старых адресов и файл `_redirects`
для хостинга, который поддерживает настоящие серверные 301-редиректы.
Команда не изменяет DNS и настройки GitHub.

Успешный итог доменной проверки:

```text
"status": "ready"
```

## 2. База и редакционная панель

Перед переносом нужно:

1. создать резервную копию проекта Supabase;
2. применить `supabase/schema.sql`, затем миграции строго в порядке,
   указанном в `MIGRATION_RU.md`;
3. создать владельца редакции и проверить его роль `admin`;
4. проверить регистрацию читателя, восстановление пароля, комментарий и
   рейтинг статьи и книги;
5. убедиться, что `service_role` задан только на сервере панели и никогда не
   попадает в GitHub Actions публичного сайта.
6. проверить загрузку аватара, сохранение любимых стран и писателей и оценку
   темы форума с двух разных читательских аккаунтов.
7. проверить создание темы и ответа, живое обновление ветки, поиск, сортировку,
   жалобу на тему/ответ и её обработку в панели редакции.

Для панели по адресу `https://probpera.ru/admin`:

```text
NEXT_PUBLIC_SITE_URL=https://probpera.ru
NEXT_PUBLIC_ADMIN_URL=https://probpera.ru/admin
ADMIN_BASE_PATH=/admin
ADMIN_ALLOWED_ORIGINS=probpera.ru,www.probpera.ru
```

GitHub Pages не запускает Next.js. Поэтому для точного адреса `/admin`
публичный сайт и панель должны находиться за единым Node.js-хостингом или
обратным прокси. Без общего прокси безопасный вариант — отдельный поддомен:

```text
NEXT_PUBLIC_SITE_URL=https://probpera.ru
NEXT_PUBLIC_ADMIN_URL=https://admin.probpera.ru
ADMIN_BASE_PATH=/
ADMIN_ALLOWED_ORIGINS=admin.probpera.ru,probpera.ru,www.probpera.ru
```

В Supabase Auth нужно заранее добавить разрешённые адреса возврата для
публичного сайта и фактического адреса панели.

## 3. Старые адреса и SEO

- Все 157 исходных адресов статей `/read/...` имеют точное сопоставление с
  новой статьёй.
- Старые страницы разделов ведут в соответствующий фильтр журнала.
- Новые страницы получают читаемые URL, canonical, Open Graph, JSON-LD и
  исходный HTML текста.
- В `sitemap.xml` входят только конечные индексируемые страницы.
- `robots.txt`, RSS и web manifest создаются для выбранного домена.
- Неизвестные адреса получают отдельную страницу 404 с `noindex,follow`.

### Полнота переноса статей и изображений

Перед переключением домена обязательно выполнить:

```text
npm run content:audit
npm run media:audit
npm run media:audit:legacy
```

Проверка `media:audit:legacy` сопоставляет каждую из 157 старых публикаций с
новой версией и контролирует заголовок, главное изображение, каждое вхождение
изображения внутри текста, количество, порядок и доступность файлов. Текущий
эталон импорта: 157 главных изображений и 657 вхождений иллюстраций внутри
текстов. Пропуск повтора, перестановка изображения или недоступный файл должны
останавливать выпуск.

Дополнительно вручную открыть материалы с боковыми изображениями, галереями и
коллажами: проверить порядок, подписи, увеличение изображения, навигацию
клавишами и отображение на телефоне. Авторский текст и заголовки при этой
проверке не редактируются.

GitHub Pages отдаёт созданные HTML-страницы перехода, но не позволяет
настроить серверный статус 301 для каждого старого адреса. Для максимально
чистого SEO-переноса нужно разместить содержимое `dist` на хостинге/CDN,
который применяет созданный файл `_redirects`, либо перенести эти правила в
конфигурацию выбранного прокси.

## 4. Последняя ручная приёмка

Проверить на временном адресе:

- главную на ширине 360, 768, 1440 и 1920 пикселей;
- меню клавиатурой, видимый фокус и режим уменьшенного движения;
- глобус: drag, touch, колесо, hover, клик, совпадение контура и страны;
- фильтры стран, писателей, книг и статей;
- книгу дня, календарь, интересный факт и реальные даты;
- тёмную, светлую и книжную темы;
- карточку книги, связи с писателем и упоминания в статьях;
- регистрацию, вход, комментарии, рейтинги и модерацию;
- форум: все десять веток, поиск и сортировку, аватары, репутацию, тему,
  ответ, оценки, жалобы и редакционную очередь;
- статью с одной иллюстрацией и статью с большой галереей: увеличение,
  подписи, стрелки, Escape и корректный счётчик;
- VK, Telegram, OK, Дзен и Boosty;
- 10 наиболее посещаемых старых URL и 10 случайных статей;
- `sitemap.xml`, `robots.txt`, `rss.xml`, `404.html` и
  `.well-known/security.txt`.

## 5. Переключение и откат

1. За сутки уменьшить TTL.
2. Зафиксировать старые DNS-записи и сделать экспорт Tilda.
3. Настроить домен на целевом хостинге и дождаться сертификата HTTPS.
4. Только после проверки HTTPS переключить A/ALIAS/CNAME.
5. Проверить основной домен и `www`; выбрать `probpera.ru` главным.
6. Добавить новый sitemap в Яндекс Вебмастер и Google Search Console.
7. Наблюдать ошибки 404, входы, публикации и комментарии не менее 48 часов.

Если критическая функция не работает, вернуть сохранённые DNS-записи,
восстановить предыдущий публичный сайт и не удалять базу нового проекта.
