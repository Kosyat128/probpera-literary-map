# Локализованные HTTP 404: локальная подготовка

Канонический origin сайта остаётся GitHub Pages: [.github/workflows/deploy-pages.yml](../../.github/workflows/deploy-pages.yml). Его корневой `404.html` сам по себе не выбирает английский документ по `/en/`. Уже существующий генератор создаёт [RU/EN error HTML](../../scripts/mobile/public-locale-pages.mjs); этот модуль связывает их точные байты с отдельным Cloudflare Worker перед тем же origin.

[Обработчик](handler.mjs) делает один исходный `fetch(request)`. Только HTML-ответ `404` на документный GET/HEAD внутри `https://probpera.ru/ru/` или `/en/` получает соответствующее готовое тело. Язык определяет путь. Query, cookies и `Accept-Language` не попадают в шаблон. Существующие успешные страницы, перенаправления, остальные статусы, API, ресурсы, вложения, range-запросы и не-HTML ошибки проходят без замены. Ответ HEAD не содержит тела. Исходный поток 404 отменяется без чтения в память.

Заменённый ответ сохраняет HTTP 404 и исходные security headers. Если canonical security header отсутствует, применяется действующее значение из [существующей конфигурации edge security](../../scripts/cloudflare/configure-edge-security.mjs). Заголовки старого представления (`Content-Length`, encoding, validators, digest) удаляются; `Content-Language` соответствует телу, `Cache-Control` и оба CDN cache-control устанавливаются в `no-store`, `X-Robots-Tag` - `noindex, follow`. Сбой origin даёт пустой 502 без отражения диагностики. Это не отменяет необходимую будущую проверку правил Cloudflare cache/security в действующей зоне.

[Генератор артефакта](../../scripts/mobile/build-public-not-found.mjs) вызывается из [domain build](../../scripts/build-domain-release.mjs) после создания locale pages. Он проверяет их SHA-256 по `dist/locale-routes.json`, язык, canonical/noindex, отсутствие скриптов и встроенных обработчиков событий, наличие локальных ресурсов HTML и CSS closure. Связь с точным Pages artifact записывается в `dist-public-locales/artifact.json`; Worker включает только два inert HTML-документа и runtime. Исполняемый JavaScript приложения и каталоги в него не копируются. Сам edge artifact находится вне `dist/` и не входит в существующую Pages upload.

`dist-public-locales/` допускает перезапись только собственных проверенных файлов. Symlink/junction, пересечение с публичной папкой, чужие файлы, повреждённый предыдущий worker, stale HTML или отсутствующие зависимости останавливают генерацию. Манипуляции каталогами не удаляют публичную сборку.

[Draft config](wrangler.draft.jsonc) содержит `routes: []`, `workers_dev: false`, `preview_urls: false`. Совместимость закреплена на `2026-08-18` - последней дате, поддерживаемой установленным workerd; локальный тест читает именно эту дату. Запуск генератора не вызывает Wrangler, API Cloudflare, деплой или изменение DNS. `deployed: false`, `activeRoutes: []`, `releaseReady: false` и исходный `hostStatusRoutingConfigured: false` остаются честным состоянием. Перед будущей публикацией нужно отдельно проверить и согласованно активировать точные Pages/edge artifacts и scoped routes; текущая подготовка не доказывает production routing или редакционную готовность EN.

[Unit tests](handler.test.mjs) проверяют условия подмены и сохранение ответов. [Artifact tests](../../scripts/mobile/build-public-not-found.test.mjs) проверяют хеши, зависимости и безопасную перезапись; один тест выполняет сгенерированный bundle в настоящем workerd через установленный Miniflare, направляя его единственный outbound fetch в HTTP origin на loopback. Этот тест проверяет HTTP 404 RU/EN, HEAD, 200, redirect и JSON asset response. Он не подключается к production origin и не имитирует подтверждение настройки Cloudflare zone.

Официальные ограничения инфраструктуры: [GitHub Pages custom 404](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site), [Cloudflare Worker Routes](https://developers.cloudflare.com/workers/configuration/routing/routes/), [Worker и origin/cache request path](https://developers.cloudflare.com/cache/interaction-cloudflare-products/workers/).
